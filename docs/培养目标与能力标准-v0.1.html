《LLM 智能体的原理、系统与协作》

培养目标与能力标准 · v0.1

日期：2026-09-17
状态：研究式学习与课程筹备用建议稿
面向：课程负责人、参与建设的研究者，以及未来修读课程的硕士与博士生
项目工作名：Agents 万事通

本文件定义培养目标、知识边界、实践深度和达标证据。当前首先服务于课程负责人的系统学习与研究；正式学时、学分、授课顺序和学生工作量，根据实际复现与试教再确定。所有实验均为待实施设计，文中没有宣称已经取得实验结果。

1. 培养使命与项目定位

1.1 培养使命

面对陌生领域中的真实任务，能够建立任务与评价标准，联合设计模型、数据、harness、工具环境和推理服务；能够沿着系统各层定位问题，通过可复现实验改进表现，并解释方案的适用条件、代价与局限。

培养对象应同时具备端到端交付能力、机制理解、研究判断与知识迁移能力。FDE 在本文指深入业务现场、承担端到端交付的工程师，其任务定义和交付能力是本课程画像的一部分。

1.2 已对齐的建设原则

  1. 正式课程名采用《LLM 智能体的原理、系统与协作》。
  2. 课程负责人先深入各个知识板块，再决定教学取舍；不先用一学期限制学习范围。
  3. 教育目标是 AI 全栈通才与方向专才的结合。广度体现为跨层理解与诊断，深度通过复现、测量和研究证据体现。
  4. 重要历史技术节点应学习其问题背景、机制和适用边界，必要时安排复现与迁移实验。
  5. 心理学、神经科学、社会学、组织研究和教育学通过具体问题与证据进入课程。
  6. QuantML 保持独立运行，作为可选案例。主学习路线覆盖软件、知识服务、科研及其他领域。
  7. 课程材料逐步沉淀为知识节点、原始文献、最小实现、实验记录、反例和教学说明。

1.3 最终应能完成的工作

毕业者应能接手一个信息不完整、预算有限、会出现失败的任务环境，完成需求澄清、基线建立、模型与系统选型、实现、评价、交接和后续改进。他应能回答：

  • 哪一类任务值得引入模型决策，哪些步骤已有可靠的确定性实现？
  • 一个失败主要来自能力不足、信息不足、状态错误、工具接口、资源约束，还是评价方式？
  • 增加模型能力、推理计算、检索、训练数据或 Agent 数量，哪项干预最值得先试？
  • 一项改进换到不同任务、模型、数据分布或硬件条件后，为什么可能失效？
  • 人承担了哪些判断与补救工作，这些投入是否已经计入系统成本？

2. 共同语言与证据边界

2.1 关键对象

对象 本课程采用的工作定义 需要辨认的边界
语言模型 通过参数化计算，在给定条件下产生 token 分布的模型；多模态模型还接受其他形式的输入表示 模型权重、推理状态、外部知识与运行时逻辑属于不同对象
Agent 围绕目标，在环境中反复观察、选择行动、获取反馈并更新工作状态的系统 自动运行不自动意味着具有模型驱动的自主决策
Workflow 对任务步骤、依赖关系和控制流程的组织 预定流程与动态决策可以组合使用
Agent harness 将模型组织成可运行 Agent 的系统，包括上下文准备、工具执行、状态、事件、资源控制和结果处理 应能区分复用现成运行时、增加业务编排、修改运行时内部机制
推理服务 装载模型并执行、调度生成请求的服务系统 与业务层任务规划、长期记忆和验收逻辑分别建模
上下文 一次模型计算实际获得的信息及其表示 硬盘上存在的文件不一定已经进入上下文
持久记忆 跨调用或跨会话保存、选择、更新并再次使用的信息 必须说明写入、检索、时效、冲突、更正与删除机制
轨迹 一次任务执行中可记录的观察、输出、工具调用、反馈与状态变化 可见推理文本不等于可直接观测全部内部计算机制

上述术语用于统一课程中的系统边界。Agent 与 workflow 可参考 Building effective agents；harness、轨迹与环境最终状态的区分可参考 Demystifying evals for AI agents。

2.2 “压缩”的四个维度

讨论压缩时，必须同时写明压缩对象、算法、执行位置和保真标准。

操作 作用对象 常见产物或结果 必须检验什么
会话 compaction 消息、工具结果及会话状态的表示 摘要、保留消息或服务商定义的压缩项 后续行动是否保留必要约束与信息
结构化 handoff 任务目标、事实、进度、决策、未完成项 可阅读、可版本化的交接材料 下一会话能否恢复真实工作状态
持久记忆提取 可跨任务复用的经验或事实 文件、数据库记录、检索条目等 来源、适用范围、时效与更新正确性
KV 量化或裁剪 注意力推理状态中的数值或条目 更低精度或更少的缓存状态 数值与任务质量变化、长程依赖损失
前缀缓存复用 已计算的相同兼容前缀状态 避免重复 prefill 命中条件、兼容性、冷暖缓存差异
分层存储与迁移 缓存所处介质和位置 GPU、主存与存储后端之间的数据移动 传输与重计算代价、命中率和延迟

“本地压缩”在本文不作为独立算法名。应使用“客户端管理的会话摘要”“本地保存的 handoff”“服务端执行的压缩”等具体表述。客户端触发、文件在本地保存、模型在本机推理，是三个独立属性。

Claude Code 的公开文档描述了清理旧工具输出、必要时摘要会话的上下文管理，以及 /compact 的定向摘要用途。持久记忆文件有独立的加载和维护机制。因此，/compact 不能直接等同于创建一套 handoff 文档或长期记忆。Claude Code 工作原理，Claude Code 记忆机制

OpenAI 的公开 compaction 接口提供不供人直接解释的加密压缩项。接口行为可以被测试，其未公开的内部实现不能被当成已知的 token 删除、普通摘要或 KV 裁剪算法。OpenAI Compaction

2.3 自改进与 RSI

RSI 在本文按 Recursive Self-Improvement 理解。相关研究的用法并不完全统一，本课程采用以下操作性分类，而不以一个标签代替实验说明。

被改变的对象 可能的改进方式 应报告的事实
知识库、记忆 增补事实、重构条目、修正过期知识 哪些外部资产改变，依据来自哪里
Prompt、工具、harness 修改接口、提示、控制逻辑、检查器 哪些运行策略改变，版本与验证结果
模型参数 微调、蒸馏、偏好学习、强化学习 数据、目标、更新过程与退化情况
改进过程本身 修改任务生成、搜索、训练或改进策略 新过程能否在独立条件下产生更有效的后续改进

自改进可以发生在模型权重之外。若使用“递归”一词，应明确改进结果如何反馈到未来的改进过程，并检验多轮效果；不能从单次收益推断无限持续进步。

两个不同的公开参照是：通过修改 Agent 代码并执行基准检验的 Darwin Gödel Machine，以及让模型生成适配数据和更新指令、再评价更新后表现的 SEAL。这些工作支持研究路线的可行性，不直接验证本项目听闻的具体业务案例。

2.4 证据等级

所有讲义和研究报告应区分：已验证的实现事实、论文在其设置下报告的结果、工程经验、类比、待检验假设。模型卡中的分数、演示和内部传闻不能自动升级为跨场景结论。

人脑、组织和教学类比必须分别说明功能层、算法层和实现层的对应关系。语言表现、任务能力与解释忠实性应单独评价。语言与思维的区分，推理文本的忠实性研究

3.2 深度等级

等级 能力表现 典型证据
L0：辨认 能辨认对象和术语，指出未知部分 概念图与问题清单
L1：使用 能按文档运行、改变配置并描述结果 可重复的使用记录
L2：重建 能解释机制、实现缩小版本、预测局部变化 推导、最小实现、预测与测量
L3：研究式掌握 能独立比较方案、诊断失败并检验迁移 对照与消融、原始数据、边界分析
L4：研究贡献 能提出并检验新的机制、方法或适用边界 有贡献的问题定义、可靠研究结果及可复现材料

L4 可以体现为有价值的阴性结果、反例或评价方法，不以刷新榜单或论文录用为必要条件。

课程负责人路线：九个模块均以 L3 为目标，通过跨层项目检验整体能力，并逐步形成 L4 研究成果。学生版本的建议起点：共同基础达到 L2，硕士在至少两个模块达到 L3；博士在此基础上完成一个 L4 研究问题。正式教学标准须由试教工作量和培养方案进一步定标。

3.3 评价维度

每个实践成果分别评价六个维度：机制理解、实现与可复现性、实验有效性、资源判断、迁移与局限、个人理解与沟通。使用上述 L0—L4 描述，保留维度分布，不用一个平均分隐藏关键短板。

共享验收要求：结论与证据一致；他人能按说明复现主要结果；保留失败运行；区分观察与推测；能解释关键实现。依赖泄漏评测、无法核对的结果或未说明的人工补救，不构成对应能力的达标证据。

5. 九个知识模块的能力标准

M1. 语言模型的能力从哪里来

必须能解释： 分词与编码、条件概率分解、embedding、因果注意力、位置表示、残差与归一化、前馈网络、训练目标与生成。区分 encoder、decoder 和 encoder-decoder；理解 Dense、MoE、MHA/MQA/GQA、潜在状态和混合架构的设计空间。区分总参数、激活参数、计算量与驻留内存。

必须亲手复现： 用 PyTorch 构建可训练的小型自回归语言模型；明确训练所用目标、掩码与张量形状；核对一段前向计算或梯度；实现有缓存和无缓存的生成并检查数值误差。至少做一项架构改变，在明确的训练或推理预算下比较。

必须实际测量： 训练与留出损失、任务表现、参数量、内存、生成速度；在改变长度、数据或架构时记录预测与实测偏差。跨 tokenizer 比较时，说明 token 口径差异，不能直接用不同 token 定义下的 perplexity 排名。

可以继续研究： 表示、归纳偏置、模块化、稀疏路由、长程依赖和状态压缩如何共同影响任务能力。多模态与具身方向扩展输入表示和行动空间，沿用相同的机制与评价要求。

达标证据： 可运行模型、关键推导、至少一个受控改变及反例、从模型配置到资源估算的说明。原始入口：Transformer、Switch Transformer、GQA。

M2. 数据与能力塑造

必须能解释： 预训练、继续预训练、SFT、参数高效微调、蒸馏、偏好学习、强化学习、可验证奖励；策略、奖励、信用分配和分布偏移。理解数据清洗、去重、混合、来源、难度、多样性与污染；区分教师输出模仿、可获得 logits 时的分布蒸馏，以及学生自身轨迹上的纠正。

必须亲手复现： 完成小模型预训练；建立任务资产到合成数据的流程；在一个真实工具接口或可执行模拟环境中生成并验证轨迹；完成一次 SFT/蒸馏实验，再选做一种偏好或奖励驱动更新。保留基础模型、检索或提示改进的对照。训练中正确处理工具观察、模型输出和 loss mask。

必须实际测量： 数据通过率、去重与来源覆盖、教师和验证开销、学习曲线、留出任务表现、通用能力退化、校准变化；报告训练和推理的总投入。失败或不充分的轨迹不能仅凭语言流畅度进入“正确示范”。

可以继续研究： 合成任务的覆盖与真实分布错配；教师错误传播；学生自己遇到的状态与教师轨迹之间的差异；训练数据、工具协议和 harness 的共同适配；主动索取 human knowledge delta 的策略。

达标证据： 可追溯数据、生成与验证代码、训练配置、独立评测、退化分析。原始入口：Chinchilla、Self-Instruct、DPO、DeepSeek-R1、SWE-smith。

M3. 推理、规划与验证

必须能解释： 推理时计算、串行展开、并行采样、候选选择、搜索、规划、重新规划、工具反馈、过程验证和结果验证。区分单次推理质量、搜索覆盖、选择器质量和最终任务完成率。

必须亲手复现： 为同一批可验证任务比较直接生成、分步求解、多候选与验证、带环境反馈的工具循环。选择一个必须根据中间观察改变计划的任务，记录状态和决策。

必须实际测量： 成功率、额外采样收益、选择器误判、工具与生成成本、总时长、错误恢复；分别在相同预算和相同质量要求下比较。不能把拥有正确答案 oracle 的 pass@k 当成可部署选择策略的成功率。

可以继续研究： 自适应分配计算、验证器与生成器的相关错误、可见推理解释的忠实性、不可完全观察环境下的计划与停止条件。

达标证据： 受控任务集、完整轨迹、验证器独立性说明、预算对照与失败类型。入口：ReAct、推理忠实性。

M4. 推理服务、硬件与量化

必须能解释： prefill/decode、连续批处理、分块 prefill、前缀复用、KV 分配、推测解码、PD 分离；数据、张量、流水线与专家并行；算力、带宽、排队、通信和负载分布。理解 vLLM、SGLang 的模型执行、调度、缓存和扩展接口，而非只记启动参数。

硬件部分覆盖 GPU 芯片内 SRAM、HBM/GDDR 显存、DDR 主存、SSD 与 NVMe 接口，以及 PCIe、GPU 间互连与跨机网络。具体容量、带宽、精度与内核支持以实验硬件和版本为准。

参数至少分三组：采样行为参数；引擎执行与调度参数；模型、精度与部署参数。输出长度、上下文长度和推理预算可能同时影响多项质量与性能指标。

量化部分覆盖训练后量化与量化感知训练，权重、激活、KV 的分别量化，校准、异常值、分组、缩放与混合精度。区分压缩后的存储体积、实际工作内存、内核支持及端到端加速。

必须亲手复现： 在单机运行一个开源推理引擎并读通一条请求路径；构造长度、到达率与并发受控的负载；实施一种缓存或调度干预和一种量化实验；至少运行一次可核对的跨进程并行或传输实验。多机条件可后续扩展，模拟通信不能被报告为真实集群收益。

必须实际测量： TTFT、逐 token 间隔或 TPOT、端到端时长、p50/p95/p99、吞吐、满足质量与时限的有效吞吐、显存、主存、缓存命中率、传输量、任务质量。区分冷启动、冷缓存和暖缓存，说明测量是否含排队及工具等待。

对于各层 KV 配置相同的普通全注意力 MHA/GQA，初步 KV 容量估算为：

KV_bytes ≈ 2 × 层数 × 各请求缓存 token 数之和 × KV头数 × 头维度 × 每元素字节数
运行内存 ≈ 实际驻留权重 + KV或其他推理状态 + 临时激活与工作区 + 框架开销

该 KV 公式不直接适用于所有 MLA、滑动窗口、混合或循环状态架构；也未包含分页浪费、元数据与并行复制等。学习者必须按实际模型修正估算，并核对测量。

可以继续研究： 量化校准与 Agent 工作负载适配、缓存迁移和重计算的盈亏条件、PD 分离的部署条件、混合架构的状态管理、服务端调度与上层任务规划的共同优化。

达标证据： 容量模型、负载生成器、配置矩阵、性能曲线、质量对照、预测偏差分析。技术入口：FlashAttention、PagedAttention、AWQ。实现入口：vLLM PD 分离、SGLang HiCache。

M5. 上下文、知识与记忆

必须能解释： 上下文构建、指令与证据来源、工具结果筛选、检索、重排、摘要、压缩、持久记忆、时效和冲突处理。区分会话记录、当前上下文、外部知识、任务状态与模型推理缓存。

必须亲手复现： 构建一个可追溯的上下文准备流程；比较完整历史、截断、普通摘要、结构化 handoff 和目标相关压缩；实现跨会话恢复与记忆更正。记录哪些信息是保留、重新检索、重新计算或已经丢失。

必须实际测量： 下游任务表现、关键状态保留、来源正确性、上下文占用、压缩与检索开销、跨多次压缩的退化、目标变化后的恢复能力。

可以继续研究： 预算约束下的信息选择、目标变化时的记忆策略、压缩与检索的协同、语义压缩与 KV 近似的交互、从使用反馈维护知识。

达标证据： 上下文与状态模式、可重放任务、压缩对照、信息丢失案例和成本分析。入口：Context engineering。旗舰实验见第 8 节。

M6. 单 Agent、工具与 harness

必须能解释： 工具契约、状态转换、事件、观察与行动、超时、取消、重试、幂等、检查点、恢复、任务完成判定、权限与隔离。理解哪些边界由程序和环境执行，哪些只是模型可见的指令。

必须亲手复现： 实现一个最小工具循环；为一个成熟 harness 编写业务适配；读通其任务到工具结果再到下一次模型调用的路径；注入进程中断、工具超时、重复调用、部分完成与状态过期等故障。

必须实际测量： 完成率、恢复成功率、重复副作用、错误完成声明、人工介入、总时间和资源开销；核对外部结果，而非只读 Agent 的自述。

可以继续研究： 运行状态与自然语言计划的一致性、长任务恢复、完成条件的组合、不同模型与运行时协议适配、环境设计如何改变模型能力表现。

达标证据： 架构与接口说明、状态与事件记录、故障实验、可验证的完成条件。现成运行时入口：Codex App Server。长期任务案例：Effective harnesses。

M7. 多 Agent 与组织设计

必须能解释： 任务分解、依赖、关键路径、协调方式、角色与工具权限、共享和独立上下文、通信、结果合并、冲突与相关错误。多个角色名不自动产生独立知识或互补能力。

必须亲手复现： 比较单 Agent、固定流程和至少一种多 Agent 结构；在可分解任务与强顺序依赖任务上分别测试；固定工具与评价条件，另设预算匹配对照。

必须实际测量： 质量、总计算量、关键路径时间、通信与协调开销、重复工作、合并错误、验证者漏检、人工调度成本。

可以继续研究： 按任务难度路由模型、异构模型分工、动态委派、团队记忆、证据独立性、架构与任务结构匹配。

达标证据： 依赖与通信图、单 Agent 基线、至少一种收益不足或失败条件，以及有依据的模型分配策略。受控比较入口：Towards a Science of Scaling Agent Systems。

M8. 评测、安全、可靠性与研究方法

必须能解释： 任务分布、构念与代理指标、留出和时间划分、污染、重复试验、相关样本、置信区间、多次择优、评价者偏差、版本漂移。理解提示注入、工具越权、状态泄漏、反馈或奖励被利用的失败机制。

必须亲手复现： 构建可重放评测环境；组合程序判定、环境状态核对与经校准的人评/模型评；注入受控故障和不可信输入；把一项宣称的提升拆解为可检验的因果干预。

必须实际测量： 任务质量及分层错误、评测者一致性、重复运行波动、成本、人工投入、恢复与边界行为。结果解释应明确样本与任务覆盖范围，观测到零次错误不等于普遍安全。

可以继续研究： 长程 Agent 评价、隐藏失败、评测器稳健性、知识演化中的自证循环、模型与 harness 更新的回归检测。

达标证据： 评测说明、隔离的开发与审计资产、原始运行记录、统计与成本报告、未解决问题。入口：Agent evals、LLM-as-a-judge 偏差。

M9. 人、认知、组织与学习

必须能解释： 语言表现与任务能力、解释与证据、认知卸载、元认知、信任校准、专业直觉、分工责任、交接、反馈、教学支架与迁移。神经科学部分学习证据和研究方法，明确类比不自动构成同机制结论。

必须亲手复现： 设计人机分工或知识演化实验；记录真实的人工补充和纠错；开展一次面向同伴的教学，并通过陌生问题或延后任务检验理解迁移。

必须实际测量： 人工时间、介入时机、错误升级、知识更新正确性、任务结果、学习者独立解释与迁移能力。参与者研究按机构实际要求实施，避免把同一人的重复任务误当独立样本。

可以继续研究： AI 辅助下的技能形成、组织记忆、错误共识、主动学习与人类知识增量、不同反馈形式的效果。

达标证据： 人机协议、人工投入记录、预测与反思日志、个人答辩、可验证的教学效果。直觉研究入口：Conditions for intuitive expertise。知识组织入口：KCS Double Loop。

8. 旗舰实验 A：多轮任务的上下文压缩与恢复

8.1 研究问题

在给定 token、计算与延迟预算下，设计目标相关的服务端压缩策略，检验它能否保持接近结构化 handoff 的下游任务表现，并明确相对完整历史的损失、成本和适用边界。

这里的“有效”是对指定任务分布、预算、指标和不确定性的经验结论。对通用开放任务，不宣称已经证明任意信息压缩无损；对受限状态字段，可以另外证明模式或状态不变量。

8.2 系统接口与不变量

设计一个由课程自行实现的压缩服务，输入包括目标、对话或事件、工具结果、结构化状态和预算；输出包括保留状态、摘要、证据引用、未解决事项和必要的检索指针。该服务是公开可检验的设计，不复刻或声称揭示供应商的私有压缩项。

需要单独保存并验证的字段包括：当前目标及其版本、有效约束、已执行动作及回执、关键事实与来源、精确标识符、已知失败、未完成项和可恢复工件。摘要不应覆盖可验证的事实记录。

8.3 基线与控制

条件 方法 用途
A0 完整历史 在能装入窗口的共同子集上提供参照；超窗任务标明不可用
A1 保留最近消息的简单截断 建立低成本基线
A2 普通会话摘要 检验无专门状态结构的摘要
A3 结构化 handoff 文档 对应可阅读、可交接的基线
A4 目标与预算感知的压缩 检验所提出策略
A5 压缩加可追溯检索 检验外部存储的作用，计入检索成本
A6 可用时的供应商 compaction 作为兼容模型上的黑箱参照，单独报告限制

先固定下游模型、工具、任务、压缩预算和压缩时点，比较算法。再把同一算法分别部署在客户端管理层和服务端，比较序列化、网络、延迟与运行效果。位置变化与算法变化分开检验。

如果引入 KV 量化或裁剪，另设“语义压缩开/关 × KV 近似开/关”的实验，避免把两种干预的收益混在一起。普通上下文改写后，应按新的输入重建或正确复用兼容缓存；删除文本不等于可以任意删除或保留原 KV，后者可能包含此前输入的影响。

8.4 任务与指标

任务至少覆盖：长程依赖、精确编号、目标中途变化、旧事实被更正、工具失败、部分完成、需追溯证据的结论、多次压缩和重新启动。任务生成器、开发题与隐藏审计题分离。

报告任务成功率、关键状态正确保留率、来源正确性、错误行动、重复工作、恢复时间、输入输出 token、压缩和检索开销、TTFT 与端到端时长。结果按压缩轮数、压缩比例和任务类型分层。

“接近 handoff”采用预先确定的非劣效或等效问题表达。若采用非劣效，定义允许的质量下降 δ；对配对差值 Q(A4)−Q(A3) 计算任务层面的区间，只有下界高于 −δ 时，才支持相应结论。δ 由任务容忍度在正式评测前确定；未检出显著差异不能直接作为等效证据。

样本量由预实验方差、δ 和所需把握度估算。少量任务与多次重复可以用于调试，不足以自动支持总体非劣效结论。相同任务的多个轮次或试次存在相关性，不能伪装成大量独立样本。

8.5 达标与研究贡献

最低交付为接口实现、基线、任务资产、状态模式、成本账、原始轨迹、配对分析和失败报告。结论可以是策略有效，也可以是某类目标变化使其失效。不能仅用更短的上下文或更低的摘要损失宣称任务能力被保留。

9. 旗舰实验 B：KCS 双循环与人类参与的知识演化

9.1 案例定位

案例依据课程负责人本次提供的三步描述：值班 Agent 遇到未知问题后由人类接手；每日知识演化 Agent 提炼经验并请求 human knowledge delta；再构造可能出现的问题，检验改进后的知识库。

该设计在机制上合理，可作为“人类参与的知识演化闭环”研究。KCS 的 Solve Loop 面向具体请求中的知识使用与维护，Evolve Loop 面向多次事件和知识使用模式的改进。课程将三步流程映射到这两个层次，并额外规定独立评价方法。KCS Double Loop

本文不据此认定基础模型权重已经变化，也不认定已经展示持续的递归能力增长。若以后系统会修改自身的知识演化策略或训练方法，可再扩大实验对象。

9.2 工作流程与资产

真实请求 → 值班 Agent → 回答/行动，或升级给人
                         │
                         ↓
          证据、处置结果、人工纠正与 knowledge delta
                         │
                         ↓
          知识演化 Agent → 候选知识版本与开发测试
                         │
                         ↓
          来源核对、回归检查、独立审计 → 新知识版本
                         │
                         └────────→ 后续真实请求

事件至少记录任务、时间、业务类别、知识库版本、模型与 harness 版本、检索与证据、Agent 处置、人工增量、最终结果和人工耗时。知识条目记录来源、适用条件、版本、有效时间、冲突、更正与失效关系。

“未知问题”也需要标准：缺少事实、检索失败、证据冲突、权限不足和能力不足应分别记录。模型自述信心只能作为信号之一，需校准升级策略。

9.3 开发题与审计题分离

自构造问题用于发现覆盖缺口、检查一致性和建立回归测试。最终效果另外使用预先留出的真实问题、适当按业务流程或来源划分的任务，以及未来时段的真实请求。

生成器和改库过程不能读取隐藏审计答案；更换一个模型当裁判并不自动使题目独立。审计结果若被反复用于调参，应重新界定为开发反馈，并建立新的独立评价。

知识更新中，对事实的增加需要可追溯的外部证据或明确记录的人类确认；合成题的假设不能自动变成新的业务事实。对于未知、冲突和应当拒答或升级的场景，也应构造测试。

9.4 对照与指标

建议比较：固定知识库；仅纳入人工确认增量；知识演化但不加入合成开发题；完整三步流程。尽可能在相同事件流、模型、检索与预算下回放，并将未来真实流量结果单独报告。

主要指标为未来真实问题解决率、正确升级率、错误回答与不必要升级、人工分钟数、证据支持率、过期或冲突知识错误、回归失败和计算成本。文章数量与合成题通过率可作过程指标，不能独自代表组织能力提升。

版本采用候选、验证、启用与撤回状态。课程环境保存旧版本和结果回执；知识更新不应让已解决问题丢失必要依据。

9.5 向训练与 RSI 方向延伸

第一阶段固定模型权重，确认知识和流程改进是否有效。第二阶段从经过验证的事件构造学生模型的工具轨迹或偏好数据，保留知识库改进与模型更新的独立对照。第三阶段可让系统提出改进任务生成、检索、验证或更新策略的候选，并用独立任务评价后续改进效率。

研究报告明确每轮改变的对象、人工贡献、搜索与训练预算、收益和退化。知识资产扩充、任务熟悉度增加、模型能力改变和改进方法改变分别报告。

10. 统一实验与研究规范

10.1 比较对象与预算

一次运行的身份至少包括模型与 tokenizer 版本、权重或适配器、精度、harness、提示、工具、知识库、任务、推理引擎、硬件和时间。服务商不公开某项信息时记录“不可观测”，不能填入推测值。

模型选择评价至少包含任务质量、完成时间、失败与重试、工具调用、人工介入和总体成本。跨模型的 token 数不必然等价于相同计算预算；同时记录可获得的成本、设备时间和墙钟时间。

10.2 主要指标口径

指标 约定
任务成功率 满足预定义完成与质量标准的任务数 / 被评价任务数；说明重试政策
每个成功任务的成本 比较期间全部相关成本 / 成功任务数，包含失败与补救；零成功时单独报告
人工投入 分别记录配置、标注、知识补充、审核、运行补救和后续维护
完成时间 从规定的请求起点到可验收结果；说明排队、重试和人工等待是否计入
有效吞吐 单位时间内同时满足质量与时限要求的任务量；与纯 token 吞吐分别报告
稳定性 多次运行的分布与置信区间，明确任务相关性和随机性
恢复能力 在预定义故障后完成或正确终止、升级的比例及代价

10.3 研究可信度

在正式比较前固定主要假设、任务划分、主要指标、预算、停止条件和允许的差异范围。保留调参记录，避免从许多候选中挑选最好结果后使用未经修正的置信结论。

统计分析以独立任务或适当聚类单位为基础，优先利用相同任务上的配对比较。多轮对话、同一来源的近重复问题和同一用户的重复任务，需要处理其相关性。除总体指标外，按任务难度、输入长度、来源和失败类型报告。

程序验证优先核对环境的真实结果。模型评审需要与人评或已知答案校准，并检查顺序、风格、冗长和自偏好等影响。评价者也属于需要验证的系统组件。

10.4 技术直觉与个人学习

每次关键实验前记录预测、理由、预期数量级和信心；实验后记录偏差、竞争性解释及下一项区分性实验；改变一个条件后再检验迁移。直觉的成长用预测与诊断质量观察，不用阅读数量或主观自信替代。

允许使用 AI 协作学习与实现，交付时说明协作范围。个人应能解释关键设计，在陌生扰动下诊断问题，并对 AI 产生的推导、代码和引用进行核验。

11.1 综合项目要求

一张学习卡至少回答：

  1. 这个技术解决什么具体问题？
  2. 简单方法如何工作，它在哪里遇到瓶颈？
  3. 新机制改变了什么，关键推导或状态变化是什么？
  4. 原始论文或实现实际支持什么结论？
  5. 最小复现如何进行，测量和预测是否一致？
  6. 一个反例或失效条件是什么？
  7. 换任务、模型或硬件后，应重新验证哪些假设？
  8. 学生怎样展示个人理解？
