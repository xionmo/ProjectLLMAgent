## 1. 学完这一单元具体能做什么

学习者能够从一条 token 序列推导训练目标，写出小型 decoder 的计算与状态，解释权重更新和逐 token 生成的差别，并证明 KV 复用保持同一前缀下的计算结果。

单元出口是“可解释的基线”，不是全部 M1/M2 已达 L3。随后还要完成受控架构/数据比较、失败归因与陌生条件迁移。

共同示例使用全新生成的受限任务，例如：

~~~text
SET a=2
SET b=7
ADD a b
RESULT 9
~~~

由独立程序决定状态和正确结果。记录格式与工具调用轨迹用于解释组件边界；从零训练的小模型是否能可靠执行该任务，必须另做评测。

图片输入从 U00 同步建立全景：把“图片解码、视觉编码、连接/融合”加入调用图，区分文件字节、像素、视觉 token 与文字 token。V01 在 U03 后实现正图/无图/换图对照，详见 [多模态教学包](多模态图片输入-课程与实验设计-v0.1.md)。

### 学习节奏与手动实现路线（2026-09-19）

按学习反馈，先理解问题和手算数值，再把已经理解的步骤翻译成程序。固定权重探针当前作为可选观察材料，不要求先逐行读懂，也不作为进入 U02 的门槛；等手写注意力后再回访、解释其实现。L3—L4 的最终深度保持不变。

教学补充：每个新符号先说明角色、对象类型/形状、来源与去向，再用小例子手算并连接公式。能代入公式不自动等于已理解对象的意义；不因概念曾被提及就默认掌握。一次引入少量新对象，必要时通过简短解释或预测检查理解，再逐步连接代码。

2026-09-22 补充教学顺序：先解释模块要解决的问题，再展开各参数负责什么、输入怎样决定本次贡献，最后落到公式与数值。学习者反馈：展开 W₁/W₂ 的职责之后才看清设计目标。因此“乘矩阵 → 激活 → 乘矩阵”只能作操作摘要，不能替代机制讲解；后续 FFN 优先沿用下面的三阶段职责说明。

手动实现按以下颗粒度推进，每一步先能说明输入、输出和一项可核验性质：

1. 手算一个查询位置：给定 Q/K/V，完成匹配、因果遮罩、softmax 与 V 加权。
2. 把多个位置排成矩阵，理解行/列含义；再用几行张量运算核对手算。
3. 从输入向量和可训练投影矩阵产生 Q/K/V，解释参数、激活和梯度的关系。
4. 依次加入多头、输出投影、残差、归一化和 FFN，组成一个 decoder block。
5. 接入 token/位置表示、堆叠 block 与词表输出头，形成完整的小型 decoder。
6. 在 U03 加入损失、训练、检查点与生成，再实现 KV 复用。

首次代码练习只围绕已讲清的部件，逐段解释与修改；完整模型是这些部件累积的结果。开放式学习目标沿 U01、U16—U18 的既定路线展开；encoder/decoder 的差别在 U02 用信息流和任务对照巩固。

## 3. U01：语言模型究竟在学习什么

### 3.1 讲解顺序

建议研讨 90—120 分钟，自主练习 2—4 小时，均为待校准估计。

1. 从 unigram、bigram 出发：模型输出的是条件分布。
2. 对 token 序列使用链式分解：联合概率由逐位置条件概率相乘得到。
3. 使用负对数似然，把连乘变为求和；明确平均的是哪些预测位置。
4. 分清 teacher forcing 与自回归生成：训练使用真前缀，推理使用已经生成的前缀。
5. 从 byte 编码到 BPE：tokenizer 改变序列长度、词表和统计口径。
6. 把概率目标转成真实标签、mask 和张量。

板书用普通公式：

~~~text
p(x1,...,xT) = product_t p(xt | x<t)
loss = - sum_t m_t log p(xt | x<t) / sum_t m_t

logits: [B, T, V]
inputs: tokens[:, :-1]
labels: tokens[:, 1:]
m_t: 有效目标位置的权重；PAD 或指定非学习位置为 0
~~~

byte 编码与字符编码不同；一个中文字符通常占多个 UTF-8 byte。教学 tokenizer 为 byte 值加专用 BOS/EOS/PAD ID；不要把普通 byte ID 随意兼作 PAD。BPE 词表只从训练部分构建。

### 3.2 必做实验

A. 手算一个三类别 softmax 与交叉熵，对 logits 梯度进行有限差分核对。

B. 实现 unigram/bigram 基线，在同一词表和相同切分上报告训练/验证 NLL。与神经模型比较前，先确保评价位置与 EOS 规则一致。

C. 对同一公开小文本做 byte 与自写小 BPE 编码，记录 UTF-8 byte 数、token 数、词表和可逆性。不同 tokenizer 的 token perplexity 不直接排名；如比较 bits per byte，需对同一原始文本、相同边界处理与各自完整序列似然建立共同分母。

D. 构造两个故障：标签未右移；padding 计入 loss。观察 loss 与真实生成/有效位置质量如何分离。

E. 先按来源或任务模板族切分，再构建 tokenizer 与样本。给出一例随机行切分导致近重复泄漏的情形。

### 3.3 验收与答辩

提交概率推导、数据切分清单、编码往返核对、基线指标与两份故障分析。验收不要求神经模型已训练。

独立答辩：为什么更短的 token 序列不自动代表更容易学习？为什么训练 loss 很低仍可能不会连续生成？如果 tokenizer 变了，之前的“相同训练 token 预算”还公平吗？

进阶问题：在固定设备时间下，编码效率与词表投影计算怎样改变可见的数据量？先列混杂因素，留到 U04 做研究比较。

### 3.4 随堂主题：激活函数、输出分布与损失的选择

2026-09-18 根据学习讨论补入。该主题贯穿 U01—U03，并在 U17/U18 接入蒸馏与偏好目标；不增加学习单元编号。先从任务与标签出发，明确输出的意义及约束，再选择概率模型和可优化的损失。

| 层次 | 要解决的问题 | 常见例子 |
| --- | --- | --- |
| 内部激活 | 中间特征如何经过非线性变换？ | ReLU、GELU、SiLU；在 U02 学机制和梯度 |
| 输出表示或分布 | 输出是互斥类别、多个标签，还是连续数值？ | softmax 类别分布、sigmoid Bernoulli 概率、实数均值及其他分布参数 |
| 学习目标 | 怎样利用标签、分布假设与任务代价评价预测？ | 交叉熵、二元交叉熵、平方/绝对误差、稳健损失、蒸馏或偏好目标 |

ReLU(z)=max(0,z) 逐元素截断负值，本身不保证小于等于 1 或总和为 1。把 (-1,2,3) 送入 ReLU 得到 (0,2,3)，尚未形成概率分布。如果再除以总和，则是在设计一套新的归一化方案：须处理全零输出、零概率目标及梯度等问题，不等于直接用 ReLU 替换 softmax。

**按任务选择的起点：**

| 任务与标签 | 常用输出设计 | 对应目标与需要核对的假设 |
| --- | --- | --- |
| 下一个 token 等互斥多类别预测 | 一组 logits 经 softmax 得到类别分布 | 单个正确标签的交叉熵；区分概率、准确率与校准 |
| 二分类 | 一个 logit 经 sigmoid 得到事件概率 | Bernoulli 负对数似然，即二元交叉熵 |
| 多标签，可同时成立 | 每个标签一个 sigmoid 概率 | 常用逐标签二元交叉熵；这些概率不要求相加为 1 |
| 连续数值预测 | 直接预测实数，或预测分布的参数 | 固定方差高斯似然下，均值的负对数似然与平方误差只差缩放和常数；异常值、非对称代价需另选或调整目标 |

这些是设计起点，不是唯一允许的组合。最终应核对标签质量、代价、校准、数值稳定性和独立任务表现；概率损失与最终业务指标也可能不同。

**连接已观察到的交互现象：**固定候选 4、6 的分数为 1、0，只改变正确候选 5 的分数 z：

~~~text
p5 = exp(z) / (exp(1) + exp(z) + exp(0))
L = -log(p5)

dp5/dz = p5 × (1-p5)
dL/dz = p5 - 1
~~~

这里是单个位置、单一正确标签、无类别加权或标签平滑的情况。概率对分数的局部敏感度在 p5=0.5 附近最大，靠近 0 或 1 时变小。损失对正确 logit 的导数则在 p5 很小时接近 -1，p5 接近 1 时接近 0。概率曲线变平不能直接等同于这个组合的输出梯度消失；向更早层传播还要结合其它导数。

为所有 logits 加相同常数，不改变 softmax 概率及该位置的交叉熵。提高错误候选的分数会挤占正确候选的概率，通常使该位置的损失上升；“概率上升、损失下降”在这里特指正确目标的概率。

滑块直接改变输出分数，是控制变量的数学实验。真实训练更新的是产生这些分数的参数，一次权重更新可能同时影响多个候选和其它输入。

**分阶段练习：**

1. U01：给“选一个类别”“可同时有多个标签”“预测一个实数”各写一份输出契约与损失选择理由；核对两类别 softmax 与 sigmoid 的关系。
2. U02：在同一小网络中比较线性层组合与加入 ReLU/GELU 的表示；检查 ReLU 负区间与零点的梯度处理。再区分 FFN 激活、注意力位置权重的 softmax、词表输出的 softmax。
3. U03：用有限差分核对 softmax + 交叉熵的输出梯度，再连接自动微分；比较极端 logits 下的数值稳定性。训练、验证都可算损失，只有实际执行参数更新的流程才构成相应训练步骤。
4. U17/U18：从硬标签扩展到教师概率、蒸馏、偏好与奖励，说明预测对象和优化目标怎样改变，另测校准及下游任务效果。

**实现接口提醒：**PyTorch 的 CrossEntropyLoss 接收未归一化 logits；BCEWithLogitsLoss 将 sigmoid 与二元交叉熵合并以改善数值稳定性。练习中检查“先做 softmax/sigmoid 再传给期望 logits 的损失”这一错误。接口参考：[ReLU](https://docs.pytorch.org/docs/2.14/generated/torch.nn.ReLU.html)、[CrossEntropyLoss](https://docs.pytorch.org/docs/2.14/generated/torch.nn.CrossEntropyLoss.html)、[BCEWithLogitsLoss](https://docs.pytorch.org/docs/2.14/generated/torch.nn.BCEWithLogitsLoss.html)。文档版本是本轮核对入口，不是尚未建立的课程运行环境锁定版本。

以上练习为待实施设计；当前交互只验证了数学关系，没有执行神经网络训练。

### 3.5 随堂主题：可见性、词表候选与开放式目标

2026-09-19 补入。标准全注意力因果遮罩允许位置 i 使用本次输入中的位置 j≤i，包含当前位置；并非只允许看前一个 token。关闭这项限制会开放未来位置。在输入为 BOS 2 + 3 = 5、目标右移一位时，输入位置“=”的监督目标是“5”；未来输入恰好含有“5”，无因果限制可能直接泄漏目标。

**区分三种控制：**

| 控制 | 决定什么 | 示例 |
| --- | --- | --- |
| Attention mask | 一个位置允许从哪些位置取得信息 | 因果、前缀、窗口、分块、padding 或文档边界 |
| 输入遮盖/扰动 | 实际送入网络的内容是什么 | 隐藏或替换一部分 token，再恢复原文 |
| Loss mask | 哪些目标位置进入损失 | 忽略 PAD，或在特定 SFT 方案中只对 assistant 输出计分 |

必须联合定义可见信息、预测目标、损失位置和推理流程。标准因果规则通常是固定的程序约束，与模型是否大到能“承受”未来信息无关；上下文长度、局部窗口或稀疏模式可以另作研究设计。放开未来信息同时改成合法的去噪/重建目标，是另一项任务，不能与原自回归 loss 直接排名。

**候选来自哪里：**常规 full-vocabulary softmax 对 tokenizer 的全部词表条目输出 logits。数据给出本位置观察到的目标 ID，不必另外为每个位置编造一份错误候选清单。此前的 4/5/6 是三类别教学简化。单条记录中的其它条目未被观察到，不等于它们在所有同类语境中语义错误。

开放式续写可以有多种合理结果；数据中的一个参考只是一次观测。U01 学条件分布、经验频率与单参考 NLL 的范围；U16—U18 再研究多样示范、多参考评价、教师软分布、偏好和任务级奖励。生成“合理句子”、遵循指令和完成任务需要分别建立评价。

**快速验证因果性：**

~~~text
A: BOS 2 + 3 = 5
B: BOS 2 + 3 = 8
比较：输入位置“=”处的完整词表 logits
~~~

冻结参数，关闭 dropout 等随机因素，保持前缀、位置和缓存条件一致；仅改变未来 token。对符合本设定的因果模型，两次 logits 应在约定数值容差内一致。不要只比较最终选择的 token，因为 argmax 相同可能掩盖分布变化。把前缀单独运行，与完整序列中对应位置比较，是另一项检查。

参考程序：[future_token_probe.py](../labs/E01/future_token_probe.py)。它用 Python 标准库计算两个固定权重注意力层，检查所有层有因果 mask、所有层关闭 mask、仅末层加 mask 三种条件。最后一种用来展示：前一层已经带入未来信息时，后层再加 mask 未必能消除泄漏。程序还核对权重哈希不变和零优化器步骤。它仅验证数学机制，不是训练好的语言模型。

**怎样解释 loss 突变：**

- 从同一个 checkpoint 分叉，在没有参数更新时切换 mask。如果 loss 当即变化，这次即时变化不能归因于学习率导致权重过拟合。
- 同时检查 logits 的未来扰动不变性、原始/处理输入、标签移位、有效 loss 位置及分母、缓存与位置索引；它们都可能改变测量含义。
- 关闭 mask 不保证任何模型都会降 loss；取决于模型是否利用新开放的信息。loss 降低本身也不证明 mask 有误，须检查依赖关系。
- 无 mask 在训练集和验证集上都可能获得虚假的自回归预测优势，因为验证输入也带着未来目标。必须检查仅给前缀的条件及实际生成。
- 固定学习率不自动导致过拟合，自适应优化器也不保证泛化；重复 token 不是上述问题的唯一或充分诊断信号。

这些小检查验证必要性质；有限样例通过不能替代对整个实现的审查。真实模型仍需迁移该检查并实测。

### 3.6 统一符号：从原始分数到权重、贡献与汇合

2026-09-19 根据本轮自测补充。首选阅读入口为 [HTML 交互课件 01](lessons/attention-symbols-01.html)，包含公式排版和逐项计算。教学记法统一如下；其它资料可能采用不同小写字母，需先查看其定义。

~~~text
r_ij = q_i · k_j
s_ij = r_ij / sqrt(d_k)
a_ij = exp(s_ij + m_ij) / sum_l exp(s_il + m_il)
o_i  = sum_j a_ij v_j
~~~

r、s、a 都是标量，但作用不同：r 是原始点积分数，s 是缩放后分数，a 是归一化权重。不能用“都是一个数”把它们当作同一对象。a_ij v_j 是一个来源的贡献，o_i 是沿来源位置求和的结果。标量是类型，缩放是操作。

此前 d_k=1 的例子中，原始分数与缩放后分数数值相同；新例用 d_k=4，把 [4,0,20] 依次变为 [2,0,10]、[2,0,-inf]，再得到约 [0.8808,0.1192,0] 的权重。

简单梯度下降中，Delta_w = -eta × g。对 g=-0.6、eta=0.1，更新量为 +0.06；不是对梯度和学习率作减法。

后续课件先让对象类型与步骤顺序可见，再加入手动实现。HTML 交互页为直接维护的课件源码，勿用静态 Markdown 渲染器覆盖。

本课 m_ij 是加性硬遮罩：0 不改变原分数，表示允许；-inf 令该项归一化权重为零，表示禁止。它不按绝对值表示影响程度。布尔或 0/1 可见性标志属于另外的接口编码，须单独核对含义。

在注意力归一化这一步，送入 softmax 的整行 s_i+m_i 可称为注意力 logits，每项对应一个来源位置；a_ij v_j 与 o_i 是特征向量。最终词表 logits 则由后续网络和词表输出层产生，每项对应一个候选 token。复习时应同时检查“是否已归一化”和“各分量对应什么对象”。


## 4. U02：亲手写出因果 decoder

原论文作为本单元的主阅读，按 [Attention Is All You Need 伴读路线](Attention-Is-All-You-Need-伴读-v0.1.md)分轮完成；先把已手算的注意力接到公式 (1)，随后读完整架构、训练与证据。

### FFN 的优先讲解方式：检测、开关、重组贡献

根据学习者提供的 sidechat 笔记整合（2026-09-22）。先在原论文 ReLU FFN 中建立这套理解，再比较课程实现的 GELU；两种激活的具体行为分别讲。入口：[第 49 页职责总览](lessons/unit-01-complete-slides.html#encoder-ffn) · [六页显微详解](lessons/unit-01-complete-slides.html#ffn-feature-detectors)。

以行向量记法固定一个位置 i：

~~~text
t_i = y_i W_1 + b_1              # 构造候选特征响应
z_i = ReLU(t_i)                   # 按当前输入开关，保留正响应强度
f_i = z_i W_2 + b_2              # 重组为主干宽度的贡献
~~~

这里 t_i 对应笔记中的激活前 h_i，避免与课程的主干表示 h_i 混淆；z_i 是本段内部激活，不能与词表 logits 混为一谈。y_i 来自第一次 Add & Norm 之后的 Y_E，已经可以包含上下文。

**W₁：提取 / 构造 / 检测候选特征。** W₁ 的形状为 d_model × d_ff；每一列将输入的多个分量线性组合，并加对应的 b₁ⱼ，得到一个标量响应 tᵢⱼ。可以暂称“学到的特征检测器”，回答“当前表示对这个内部方向有多强的响应”。不保证通道对应可命名的单一语义，也不只是复制输入的某一维。更宽的中间层提供更多候选通道，配合非线性增加表达选择；线性扩维本身不会凭空增加输入信息，宽度也不保证质量。

**ReLU：按输入决定哪些候选通道通过。** zᵢⱼ = max(0, tᵢⱼ)。例如 (2.3, −1.7, 0.8) → (2.3, 0, 0.8)。开关是输入相关的：参数可以完全不变，输入改变仍会改变通过的通道。正值保留强度，输出不是单纯的 0/1，也不需要归一化为概率。ReLU 自身没有可训练参数；不能解释成“负数信息不好所以删除”。

**W₂：把通过的特征对应的贡献重新组合。** W₂ 的形状为 d_ff × d_model。将其第 j 行记作 w_out_j，则 f_i = sum_j z_ij w_out_j + b_2；该行是通道 j 对输出各分量的贡献方向。笔记使用 v_j 表示这个方向，本课程改名以免与注意力 Value 混淆。例：f = 2.3 w_out_1 + 0 w_out_2 + 0.8 w_out_3 + b_2，第二通道此次贡献为零。W₂ 的元素和最终 f_i 都可以有负值；这些通道强度不要求和为 1。行列角色不能说反：W₁ 的列负责检测，W₂ 的行负责贡献方向。

**“写回”的精确边界。** W₂ 先得到 FFN 的输出贡献 f_i；各位置排成 F_E，再通过 Y_E + F_E 接入残差主干，最后按原论文 post-LN 结构归一化。W₂ 自身不执行残差加法，也没有直接替换当前 token 表示。可反复使用口诀“W₁ 提特征 → ReLU 做开关 → W₂ 重组并准备写回 → 残差相加接入主干”。

从上述分解还能看清两组参数的分工：检测方向与输出方向分别学习，W₁ 决定“对什么响应”，W₂ 决定“响应后产生什么贡献”，不要求两种方向相同；ReLU 再让本次贡献的参与情况依赖输入。

**非线性的设计作用。** 删除 ReLU 后，(yW₁+b₁)W₂+b₂ = y(W₁W₂)+(b₁W₂+b₂)，能合成一个固定仿射变换。保留 ReLU 后，可用输入相关的对角开关 D(y) 将它写为 yW₁D(y)W₂+b₁D(y)W₂+b₂：一个固定开关区域内仍是仿射，跨区域时开关可以改变，因此整体能表达分段仿射函数。不是每组参数都必然产生有用的非线性，不能把结构具备表达能力当作已经学到该能力。

**与 Attention 对齐职责。** Attention 在可见位置之间读取内容，可以包含当前位置自身；FFN 对本位置已有的表示计算候选特征、按激活规则通过、重组输出贡献。FFN 逐位置应用同一层的共享参数，输入本身却可以已有注意力汇入的上下文。

讲解核对采用同一组 W₁/W₂ 的两个输入，而不是在两例之间暗换权重。让学习者指出“哪个通道关闭”“W₂ 哪一行此次贡献为零”“何处才进行残差相加”，用解释检验职责理解，不只检验乘法熟练度。完整数值对照见第 100 页。后续讲 GELU/SwiGLU 时沿用职责分析，但重新说明其激活机制，不照搬 ReLU 的零截断规则。

原结构、维度与共享方式参考：[原论文 §3.3](https://arxiv.org/html/1706.03762v7#S3.SS3)；“检测器 / 开关 / 输出贡献方向”是本课对公式的解释方式，不视为作者保证了通道的语义。

### 4.1 教学构型与张量账

先做 D0：2 层、d=64、4 个头、短序列、FP32、关闭 dropout。正确后扩到 D1：4 层、d=256、4 个头、FFN=1024、上下文最多 512、byte 词表加 3 个专用符号。

第一版使用 learned absolute position、pre-LayerNorm、普通 GELU FFN、MHA、共享输入 embedding 与输出投影权重。这是便于核对的教学组合；RMSNorm、RoPE、SwiGLU、GQA 和 MoE 是后续明确改变的机制，不同时混入初版。

| 对象 | 形状或约束 | 必须核对 |
| --- | --- | --- |
| 输入 token | B×T | 不越词表；PAD 位置可辨认 |
| embedding | B×T×d | token 与位置相加；位置不越上限 |
| Q/K/V | B×h×T×dh，dh=d/h | 分头前后排列一致 |
| 注意力分数 | B×h×T×T | 除以 sqrt(dh)，屏蔽未来位置 |
| 注意力输出 | B×T×d | softmax 的轴是 key 位置 |
| FFN | d→4d→d | 激活与残差路径 |
| logits | B×T×V | 权重共享后参数只计一次 |

不要一开始用完整 Transformer 类替代关键实现；允许用基础张量运算和自动微分。参考算子用于核对，之后再换优化内核。

### 4.2 课堂推导与实现任务

第一段从单个查询位置手算开始：T=3，Q/K 先用一维数值，V 用二维向量，缩放因子为 1；算清匹配、遮罩、softmax 与加权汇合。随后再把 Q/K 扩为二维，解释缩放，并推广到全部位置的矩阵计算；手算理解后才用几行程序核对。

第二段加入多头、输出投影、残差和归一化。对比 post-norm 与 pre-norm 的计算图，但初版只实现已选方案，避免一次改变多个因素。

第三段讨论因果性：位置 t 的输出不能依赖未来输入。实现后固定前缀，替换其后的 token，检查前缀 logits 保持一致。这个检查比肉眼看三角 mask 更能验证整个实现。

最后画一次反向传播的依赖，检查参数有梯度、数值有限、共享权重没有重复更新。

### 4.3 正确性关卡

1. 小矩阵注意力输出与独立参考一致；关闭 dropout，使用 FP32。
2. 改变未来 token 不影响已有前缀 logits。
3. 手写注意力与所选参考算子使用相同 mask、缩放和张量布局。
4. 极短 batch 的 loss 与梯度均有限，参数量与逐模块账相符。
5. 删除因果 mask 的故障版本必须被第 2 项检出。

起始误差容差可选 atol=1e-5、rtol=1e-4，但必须记录 dtype、设备、内核和观察误差；不满足时先查计算差异，不为过关任意放宽。BF16 等精度在正确基线建立后单独比较。

**通过条件：**能解释每条路径与形状；负例被检出；能指出第一版与 Transformer 原论文架构的差异。[原始论文](https://arxiv.org/abs/1706.03762)

独立答辩：注意力矩阵为什么有 T² 个位置？多头数量翻倍而 d 不变时，哪些参数量不变？去掉位置表示后，会失去什么信息？共享 embedding 后参数计数为什么不能直接相加？

### 4.4 随堂桥接：Q/K/V、encoder 与 decoder

在某个注意力层里，每个输入位置已有一个向量表示 h_i，通过可训练投影得到 q_i、k_i、v_i。Q/K 用于计算位置之间的匹配分数，归一化后的权重用于加权汇合 V。K/V 本身不是已经计算好的“与全文关系”；较深层的输入表示可以包含前面层已汇入的上下文。

可以先用以下角色建立直觉：Q 参与决定当前查询如何读取，K 提供供查询匹配的向量，V 提供按权重汇合的内容。这些是数学计算角色，不要求每个向量都能翻译成人类语义。mask 决定哪些位置的匹配可以参与；注意力权重描述允许范围内的分配，不是对全部历史无限访问。

| 结构 | 典型可见性 | 先研究的任务 |
| --- | --- | --- |
| Encoder-only | 输入中的有效位置可双向交互，仍可有 padding/边界限制 | 表征、分类、检索；以 BERT 的遮盖词恢复作目标对照 |
| Decoder-only | 标准自回归情形中，每个位置使用当前及过去输入 | 下一 token 预测与生成 |
| Encoder-decoder | encoder 处理完整已知输入，decoder 对目标前缀保持因果，并交叉读取 encoder 表示 | 翻译、摘要等条件生成 |

原始 Transformer 同时包含 encoder 与 decoder。全篇两两可见不是 Transformer 的定义，注意力也早于 Transformer 出现；课程依据原始架构与机制理解术语，不从名字推断“每个 token 必须看全文”。

原始阅读：[Transformer 第 3 节](https://arxiv.org/html/1706.03762v7#S3)、[BERT](https://arxiv.org/abs/1810.04805)、[缩放点积注意力及 mask 的实现说明](https://docs.pytorch.org/docs/2.14/generated/torch.nn.functional.scaled_dot_product_attention.html)。

后续 U03 建立常规自回归生成基线，U10/U19 比较多 token 草稿与批量验证，以及不同生成目标的并行过程。[Speculative sampling](https://arxiv.org/abs/2302.01318)和[Medusa](https://arxiv.org/abs/2401.10774)属于草稿/候选验证方向；[LLaDA](https://arxiv.org/abs/2502.09992)采用遮盖与反向生成过程。它们不是简单关闭现有自回归训练 mask 得到的同一种方法。“并行预测后纠错”的描述不足以唯一识别某个模型。

## 5. U03：让模型学习，再复用已经算过的状态

### 5.1 先验证训练，再讨论能力

先取极小的固定训练子集，验证模型能把有效位置的 loss 明显降低。该过程是排查训练错误的调试实验，不能作为泛化成绩。保留另一个独立切分检查记忆与泛化的差别。

训练循环逐项解释：清梯度、前向、目标 mask、loss reduction、反向、梯度检查/裁剪、优化器更新、学习率与检查点。实现一种优化器即可先用 AdamW；随后用更新公式解释权重衰减和自适应状态。

梯度累积核对采用相同样本、关闭随机层，比较一个大 batch 与多个 microbatch 的参数更新。序列有效 token 数不同时，不能简单把每个 microbatch 的 mean loss 平均：按有效目标数量累计，或等价加权，使目标一致。

### 5.2 恢复实验

在固定步数保存并中断，然后恢复继续，与不中断分支比较。检查点至少包括：

- 模型、优化器、学习率调度器、必要的混合精度 scaler。
- Python/PyTorch 与已用到的随机数状态。
- 数据迭代位置、采样器状态或足够恢复的数据顺序。
- 累计有效 token、更新次数、配置、代码和数据版本。

先在确定性 D0 条件核对下一批数据、loss 和更新，再在 GPU 条件记录可重现容差。仅加载模型权重并不是恢复训练；GPU 内核差异也不应被伪装成逐位一致。

### 5.3 从全前缀重算到 KV 复用

基线每步输入完整前缀。缓存版先 prefill，保存每层 K/V；随后对新 token 计算新的 Q/K/V，并使用已有状态。

对普通 MHA，逐层缓存形状为 B×h×T×dh。MHA/GQA 普通全注意力的容量近似：

~~~text
KV_bytes = 2 × 层数 × 总缓存token数 × KV头数 × 头维度 × 元素字节数
~~~

先比较**完全相同的给定前缀**下下一位置 logits，再比较固定条件下的生成轨迹。不能用两条已经生成出不同 token 的序列继续逐位对比，而把差异全部归因于缓存。

位置偏移必须随缓存增长。若 cached prefix 长度为 P，本次 chunk 内第 i 个 query 允许访问 key 位置 j，当且仅当 j ≤ P+i。单 token decode 的已有 K/V 都可见；chunked prefill 需要包含偏移的矩形 mask。库的 causal 参数语义要按固定版本核对，不假定所有非方阵 mask 都右对齐。

### 5.4 对照矩阵

| 条件 | 目的 | 必须保留 |
| --- | --- | --- |
| 全前缀重算 | 正确性与速度基线 | 相同权重、前缀、位置和 dtype |
| prefill + 单 token cache | 核验逐步复用 | 每步 logits 误差、cache 长度 |
| prefix + 多 token chunk | 检验矩形 mask 和偏移 | 与全前缀相应位置的输出核对 |
| 位置偏移故意归零 | 验证测试能发现真实错误 | 首次分歧位置及定位说明 |
| 清除一个必要缓存块 | 验证状态缺失 | 正确拒绝/重算或可观测错误，不能静默宣称等价 |

正确性通过后测输入长度 32/128/512、固定新增 32 token 的小矩阵；上下文总长不能超过已定义位置上限，长档可将输入改为 480 或扩大后重新冻结上限。报告 prefill、decode 和总时间；计入同步与预热，记录测量范围。先不把短模型、短序列的一次计时解释成普遍加速。

CUDA 操作是异步的，计时必须使用正确的事件或同步边界。推理测量关闭梯度并保持 eval 状态；记录包含或排除编译、内存分配和输出搬运的口径。

### 5.5 验收与独立答辩

提交训练曲线、checkpoint 恢复记录、梯度累积核对、缓存等价性结果、故障负例、参数/状态/内存账和预先写下的速度预测。

答辩题：

- 为什么 KV cache 不等于长期记忆，也不等于模型权重？
- 相同权重和前缀下，cache 路径为什么应该在数值误差内一致？
- 缓存为什么可能使一个极小模型的短请求更慢？
- microbatch 平均 loss 一样，为何更新仍可能不同？
- 为什么 loss 恢复接近，但下一批数据不同，仍不能声称精确续训？

## 7. 备课者的判分锚点

以机制、实现、研究有效性、资源判断、迁移和个人表达六维分别记录。没有真实运行记录的代码阅读只计相应理解证据；“按步骤跑通”不能直接计为研究式掌握。

本单元合格的典型表现是：可以从误差首先出现的位置定位 label、mask、位置、状态或随机性的错误；能给出一个区分竞争解释的下一实验。后续 U04—U06 再检查受控干预和迁移，完成对应 L3 证据。

每次研讨结束保留一张“今天推翻了哪一个预测”的卡。没有推翻也可记录确认了什么、证据有多强及下一步边界，避免强行编造反思。

## 8. 首轮最小阅读

- [Attention Is All You Need](https://arxiv.org/abs/1706.03762)：只先读注意力、多头和模型结构相关部分，手绘计算图。
- [Stanford CS336](https://cs336.stanford.edu/)：参考模型构建、tokenization 与训练系统的课程组织；本项目实现与作业按当前单卡目标自行设计。
- [GQA](https://arxiv.org/abs/2305.13245)：U03 完成后再读，预测减少 KV 头数会改变什么。
- [PagedAttention](https://arxiv.org/abs/2309.06180)：留作 U08 的桥梁，区分“复用缓存的计算原理”和“如何管理许多请求的缓存”。

本包不要求先读完上述所有材料才能动手。优先完成一个可以验证的机制，再读它在更大系统中遇到的问题。
