图片输入多模态：课程增补与实验设计

v0.1 · 2026-09-18 · 本轮必做范围

本增补把静态图片输入接入《LLM 智能体的原理、系统与协作》的两项旗舰：既学习图片如何参与模型计算与训练，也研究它怎样影响推理服务。输出先采用文本或结构化工具参数；首轮从单图开始，再扩到同一请求的多图。

依据：培养目标与能力标准 v0.4 · 课程实施方案。新增实验 E13 包含 V01—V06 六个单元，与原有 34 单元合计 40 单元。它们插入相应先修位置，不等到文本课程全部结束才开展。

本文件是研究与备课设计。当前尚未下载或执行 VLM，以下配置是起点建议，不是本机已验证性能。

1. 要研究的完整路径

图片资产 → 解码/色彩/方向 → resize/crop/patch 或动态分辨率处理
    → 视觉编码器 → 连接/融合模块 → 与文字及位置共同组织
    → 语言模型预填充 → 自回归生成 → 文本/结构化结果
                         ↓
        视觉编码状态、LLM KV、调度与缓存的资源账

这是一张常见架构的教学分层图，不规定所有模型都以同样方式融合。课程先重建“视觉编码器 + 连接器 + 语言模型”的简单路径，再读真实模型中的多层特征、特殊位置编码、跨注意力或其他融合设计。

图片文件字节、像素、patch 数、视觉 token 数和文本 tokenizer token 数必须分开记录。Base64 是运输编码；不能把 base64 字符长度当作模型视觉上下文长度。

CLIP作为图文对齐的机制入口，LLaVA作为视觉编码与语言生成连接、视觉指令训练的入口；不把 CLIP 的检索/对齐能力直接当作完整图文对话能力。

2. 六个单元插在哪里

单元 先修与位置 讲解和实践 L3 对照与交付
V01 图片是否真的进入模型 U00 后可先观察，U03 后完成实现 结构化 image+text 请求、processor/chat template、图像解码与模型输入追踪 正图/无图/换图，配对检查答案依赖视觉证据；输入 manifest 与中间形状
V02 视觉表示与图文连接 U05 后 patch embedding、ViT、CLIP/SigLIP 类对齐目标、projector/resampler、融合与位置 小型 patch/连接器实现；冻结编码器与 LLM、改变连接器的受控实验；梯度路径图
V03 多模态数据与能力塑造 U16 后，与 U17 相连 caption、VQA、OCR、图表、指令轨迹；图文匹配、图像近重复、loss mask 基础模型/连接器适配/LoRA 等成本对照；错配数据与文本退化检查
V04 图片推理服务 U09/U10 后，接 U12/U13 预处理、视觉编码、LLM prefill/decode 分段，图数/分辨率/并发，视觉缓存 同图不同分辨率、同分辨率不同图数；质量—显存—TTFT/吞吐曲线与实际引擎日志
V05 感知、推理与幻觉评测 V01 后可开始，U19/U27 深化 OCR、图表问答、空间关系、不可见信息、依据与置信；错误分层 同一底图的反事实改动；GT 文本与真实 OCR 两种 oracle/部署对照分开
V06 图片进入上下文与工具循环 U22/U23 后，与 U28 相连 媒体引用、版本、裁剪、跨轮恢复、图中不可信指令、可追溯证据 替图、失效引用、错误裁剪、缓存污染与故障恢复；程序边界和最终状态核对

V03 的连接器学习可以用小规模受控形状/布局任务验证机制；不要求在 4090 上从零预训练通用视觉编码器或达到大型 VLM 的通用能力。冻结模块后仍可能需要穿过模块计算输入梯度，资源开销须按实际 autograd 路径测量。

2.1 对 M1—M9 的增量

模块 图片输入带来的新增能力与证据
M1 解释视觉编码、连接/融合、视觉与文本位置；核对 token/patch 与计算形状
M2 图文配对和去重；视觉指令训练的目标 mask；选择冻结模块与适配模块；检查图像/文本能力退化
M3 分开视觉证据提取错误、关系/数值推理错误和输出选择错误；必要时比较 OCR/裁剪工具
M4 把视觉编码、encoder 状态与 decoder KV 分开计量；测动态分辨率、图数、量化和缓存路径
M5 保存图片来源、内容哈希、处理参数与裁剪关系；验证跨轮图片引用和摘要保真
M6 接受并校验真实图片内容、媒体限制与模型契约；损坏输入、超时、取消与恢复
M7 视觉读取与推理分工是否有效；共享同一错误视觉描述时，多个 Agent 的错误并不独立
M8 按源图分组留出，做换图/反事实对照；检查答案从文件名、caption、元数据或 OCR 文本泄漏
M9 测量人类核图、标注、裁剪与纠错投入；用未见图像检验独立判断和教学迁移

图片输入是本轮建设要求；不把它仅保留为某个选修方向。各模块仍按已有 L3—L4 定义评价。

3. 4090 上的首个模型与实现路线

第一候选采用官方开放权重 Qwen/Qwen3-VL-2B-Instruct。选择它是为了先在较小尺度追踪完整路径；不是模型能力排名，也没有确认它在本机当前环境已能运行。官方模型页提供图片与文字输入示例、架构说明以及 Transformers/引擎入口。

实际实施时冻结模型和 processor 的 revision、许可、Transformers 与推理引擎版本。模型卡的历史安装说明可能落后于当前发布，不直接照抄其中的“最新版”命令。查对应模型类、配置与支持矩阵后再安装。

先使用该模型的 Transformers 路径完成单图正确性与输入检查；相同模型、processor 和解码配置稳定后接 vLLM。两种实现可能使用不同内核，应先核对输入与输出行为，再测性能。vLLM 图片输入协议

首轮容量探测建议：

变量 起点 之后如何增加
图片数量 1 基线通过后测 2、4，设明确每请求上限
原始测试边长 224 与 448 的受控方图 扩到 896 或非方图；记录 processor 实际 resize/patch 结果
文本与生成 短提示、生成上限 64 token 固定后再改变输出长度，避免混入 TTFT 对照

上下文上限 由文字加实际视觉 token 预估，先小规模验证 不采用模型卡最长上下文作为默认实验负载
权重更新 首先冻结模型做推理 V02/V03 再测连接器或 LoRA；不先做全参 VLM 训练

2B 的名称不能直接当作所有模块的准确参数总数。显存需包含视觉编码器、语言部分、连接器、处理激活、视觉相关状态、decoder KV 与框架工作区；训练再加梯度和优化器等。

对“把视觉 token 放入 decoder 序列”的架构，普通全注意力 KV 估算要把实际视觉 token 计入缓存长度。跨注意力、额外 encoder 状态与混合模型需分别建模，不能套同一个公式。

4. 第一项完整图片实验 E13-A

4.1 研究问题

当只改变图片里的事实而保持文字问题不变时，系统是否随视觉证据正确改变答案？这种能力随分辨率和处理预算怎样变化？

先验收视觉依赖与测量链路，再研究训练或服务优化。会说“看到了图片”不是图片输入正确的证据。

4.2 任务组成与数据契约

第一轮开发小集建议 24 个源场景，每个场景 2 张反事实图片，共 48 张；按下面三类各 8 个源场景组织。这是发现问题的教学规模，不足以估计通用能力或罕见失败率。

场景 图片来源 保持什么不变 改变什么 判定
文字读取 新生成的简短编号、数值与表格图 字体/背景/问题 一处真实可见字符或数值 预定义归一化后的 exact match，必要时字符错误率
图表读取与简单推理 由已知数值生成柱图、折线或表格 样式、问题及大部分数据 一根柱值、一个排序关系或表项 可程序计算答案；数值容差预先定义
视觉关系 几何形状/物体布局的自建图片 任务措辞与干扰物 数量、相对位置、颜色或目标存在性 按生成场景的独立真值判定

不得把答案写入输入文件名、提示、alt text 或模型可读元数据。源图与其裁剪、缩放、同源反事实版本必须归在同一数据组；以后划分训练/开发/审计时整组划分。生成器和场景真值不能被模型侧读取。

无图或不可读图片的真值状态是“证据不足”，不能强迫判为某个视觉答案。低分辨率导致细节不可辨认时，允许预定义的拒答/不确定输出，并单独记录覆盖率。

4.3 需要运行的对照

条件 输入 解释用途
I0 正常图 图片 A + 问题 Q 基线视觉问答
I1 无图 同样 Q，明确无图片内容 检查语言先验与任务可猜测性；单独评价适当拒答
I2 反事实换图 图片 B + 完全相同的 Q 以 B 的真值评分，检查答案是否随图正确改变
I3 文本 oracle 原图中必要事实的人工/程序真值文本 + Q 诊断上界：隔离视觉读取困难；不当作可部署 OCR 方案
I4 OCR/工具路径 真实 OCR 或裁剪结果 + Q 计入工具错误、时间与成本；对图表/关系任务不预设充分
I5 分辨率变化 同一源图的各个处理预算 同时测任务质量和实际视觉 token/时间/内存
I6 配对错位诊断 将批次中的图与问题故意错配 检查装配/排序错误；只在定义了新配对真值或证据不足标准时评分

I2 不能仍按 A 的答案判分。I3 的真值文本是一项明确标注的诊断干预，不向正常模型分支泄漏。

4.4 分段计时与资源记录

记录总请求时间，并在可观察范围内细分：读图/解码、预处理、视觉编码、语言 prefill、decode。服务客户端的 TTFT 另含排队与协议开销；如果框架不能可靠拆出某一项，写“未单独观测”。

每个输入保存图像哈希、原始尺寸、实际处理尺寸、patch/grid 信息、实际视觉 token/占位符展开、文字 token、生成 token、模型/processor 版本、dtype、峰值内存、冷暖缓存和请求结果。

不能用原始像素比例推断视觉 token 比例，也不能把压缩 JPEG 文件大小当作编码开销。

4.5 最小结果表与通过条件

场景族/处理预算 可回答率 条件准确率 反事实双题均正确率 适当拒答 实际视觉 token TTFT/总时长 峰值内存
待正式运行

同时报告全体可回答题的成功率，避免只在模型选择回答的题上计算准确率而掩盖拒答。反事实双题均正确率以成对场景为单位；重复提问不是新的独立样本。

通过 E13-A 的链路关卡，需要：

  1. 实际送入图片内容，有可检查的处理和模型输入记录。
  2. 正图、无图与换图分支真实执行，答案/拒答按各自真值评分。
  3. 至少定位一次预处理、装配、视觉读取、推理或输出格式的失败。
  4. 能解释一组质量与资源的变化，并记录无法分离的因素。
  5. 保留原始结果和人工介入，明确这一小开发集的局限。

不预设某个候选必须达到 90% 才算课程合格。链路正确但效果差时，解释失败本身就是研究对象；训练与优化收益需要后续独立数据检验。

5. 第二项实验 E13-B：连接器与多模态适配

在 V02/V03 用小型受控环境研究“什么参数使图片影响答案”。固定视觉编码器与语言模型，先训练连接器；条件允许再比较连接器加 LoRA。保持语料、训练样本暴露与主预算可核对。

记录哪些参数 require_grad、哪些模块真正更新、图像位置怎样进入 loss、用户提示/视觉占位/PAD 与 assistant 目标如何处理。训练 mask 按实际模型接口核对，不能只沿用文本 SFT 的字段位置。

必要对照包括未训练连接器、匹配图文训练、错配图文训练，以及同预算适配方案。检测图像题提升、文字能力退化和对新布局/新字体/新长度的迁移。错配数据是受控负例，隔离保存。

首轮不复现大型多模态预训练的规模结论。对真实 VLM 的改动还需核验视觉编码器或语言部分的冻结策略、连接器结构和模型专用融合路径。

6. 第三项实验 E13-C：图片服务与缓存

在 V04 中分别测：媒体解码缓存、视觉特征缓存、语言模型前缀/KV 缓存。每一种缓存都写出身份条件，包括图片内容、处理参数、模型/processor 版本，以及相关位置/上下文。

同一图片路径的文件改变、相同图片使用不同裁剪、图像顺序改变，都是必要失效测试。把“图片 hash 一样”当作整条模型前缀可复用的充分条件是不成立的。

比较只改变语言部分精度与同时改变视觉部分的方案；检查量化库和引擎真正覆盖了哪些模块。不把文本模型上的量化效果直接外推到视觉编码或 OCR 细节。

单卡首轮只声称同一 4090 上的服务结果。视觉编码与语言 prefill 的分离部署可以先建成本模型，真实跨设备收益另需设备实验。

7. L4 研究入口

以下是候选问题，须再核查现有研究与具体差距：

  • 在图表/OCR 与视觉关系任务之间，自适应选择分辨率、裁剪或视觉 token 预算，是否优于等成本固定分辨率？
  • 视觉编码、连接器和语言层对量化误差的敏感性是否不同，质量约束下的混合精度如何选择？
  • 图像特征缓存与语言前缀缓存怎样共同改善重复图片、多轮问答的有效吞吐，何时反而浪费内存？
  • 分开记录视觉证据与推理能否改善失败定位，而不会因多 Agent 转述引入新的事实丢失？
  • 训练/服务改进器能否把文字任务学到的研究策略迁移到图像任务？沿用 E10 的共同检查点和继承/重置对照。

新架构、算法或有价值的适用边界均可作为贡献；“调用了一个 VLM 接口”本身只支持使用能力。
