模型负责什么？

根据输入产生输出分布，进而形成文字或结构化调用建议。

系统负责什么？

决定是否执行、记录参数和结果、处理失败与重复请求、验证任务完成。

“我已完成”是模型输出。实际完成还需要工具轨迹、文件或外部状态的证据。

纠正信息进入上下文，不等于模型被训练了

固定参数推理

原上下文 → 回答错误
追加纠正 → 新的上下文 → 回答改变

这可以在 θ 完全不变的情况下发生。

参数训练

构造目标 → 算损失 → 反向传播 → 优化器更新 θ。

必须有明确的训练计算与更新步骤。

单个样本可以用于调试或产生梯度，但它通常不足以评价泛化。不要从答对一道题反推模型权重已经更新。

图片数字算错：沿着证据定位第一次偏差

检查点要看什么能缩小哪类问题
输入与读取实际图片、模型读出的数字图片传输、预处理或识别
工具调用真实调用参数，而非事后文字解释数字提取与调用构造
工具与回答工具返回值、最后答案计算执行或结果转述
若计算器确实收到了 100 和 180，应先核对这是否是图片中的数字；换成干净数字图，是一种受控对照。

普通识别错误、推理时的对抗输入和训练数据投毒是不同假设。输出异常本身不能证明攻击意图。

语言模型学习的是条件分布

预测 xₜ 时，条件是它之前的 token。对一个序列的概率，可以按这条链逐项相乘。

一次预测

给定前缀，输出下一位置对整个词表的分布。

一段生成

选出一个 token，加入前缀，再调用相同参数的模型继续。

“按 token 生成”描述输出顺序；每次前向中的矩阵计算仍可大量并行。

logits：给每个候选一个实数分数

对象每个分量对应什么
隐藏表示 hₜ模型内部的特征坐标
词表 logits zₜ一个候选 token
注意力分数 sᵢⱼ一个来源位置 j
普通全词表输出头一次给所有候选打分；训练标签提供本次观测到的目标，并不逐个手工提供“错误候选”。

softmax 把一组分数变成相对概率

共同加一个常数会在分子、分母中约掉；实现时常减去最大分数，避免指数溢出。

影响概率的是分数之间的相对关系。共同平移不变，整体乘一个系数通常会改变概率的集中程度。

ReLU 本身不保证输出和为 1。内部激活、概率变换与损失函数需要按用途区分。

交叉熵：目标 token 获得了多少概率？

p(目标) = 0.9

L ≈ 0.105

p(目标) = 0.6

L ≈ 0.511

给真实目标更高概率，会降低这一个位置的负对数似然。

单个样本损失更低，不足以说明泛化更强。训练、验证、测试损失需要连同数据切分和信息可见性一起解释。

梯度：损失对各个变量的局部变化率

对 one-hot 目标的 softmax 交叉熵，正确类别的导数为 pᵧ − 1；其它类别为 pⱼ。

导数的符号

说明小幅改变该变量时，损失往哪个方向变化。

导数的大小

说明局部敏感程度；实际更新还由学习率与优化器决定。

只看 softmax 概率曲线是否变平，不能判断完整损失到参数的训练信号。

输出梯度，怎样传回模型参数？

参数 θ
→
多层计算 → logits
→
概率与损失

反向传播沿相反方向应用链式法则，汇总所有依赖该参数的路径。

同一个参数在多个位置使用时，各位置对它的梯度会累加。一次前向产生激活，反向计算梯度，优化器再更新参数。

梯度与参数更新量不是同一个量

最简单的梯度下降：若梯度 g = −0.6，学习率 η = 0.1，

参数增加约 0.06；这与“给用户消息加一句纠正”是不同操作。

这只是单步 SGD 的例子。后面的 AdamW 会引入梯度统计与权重衰减，但仍需显式执行 optimizer.step。

完整序列BOSABEOS
输入BOSAB—
目标ABEOS—
inputs = tokens[:, :-1]

预测目标 B 的输入位置是 A。虽然 B 也在整条训练数组中，该预测位置不能通过注意力读取它。

BOS 是起始标记，EOS 是结束标记；其具体 ID 由 tokenizer 约定。

训练能并行预测，生成却依赖已生成的前缀

Teacher forcing

训练时提供真实序列，用 causal mask 限制每个位置的可见范围。

各位置的预测与损失可以在一次前向中一起计算。

自回归生成

下一步输入包含模型实际生成的 token。

早先选错的 token 可能改变之后遇到的上下文。

低训练损失与长段生成表现不是同一项证据。需要在仅给前缀的条件下单独检验生成。

怎样检验“较早位置读不到未来”？

  1. 固定参数、前缀和位置设置，排除 dropout 等随机性。
  2. 只替换未来目标 token。
  3. 比较较早位置的 logits 是否保持不变。

正反对照

正确的各层 causal mask 应保持不变；故意去掉 mask 的版本应被检查发现。

为什么不能只查末层？

前层若已带入未来信息，末层再遮罩也不一定能消除它。

项目的 future_token_probe 是固定权重机制探针，不是已训练的完整 Transformer。

attention mask 与 loss mask 管的是不同事情

对象作用典型范围
Mᵢⱼ：注意力遮罩位置 i 能从 j 读取信息吗？query × key 位置
mₜ：目标有效标记这个预测位置计入损失吗？各目标位置
PAD 标签通常不计入目标平均；但只忽略它的 loss，不等于已经屏蔽了注意力里的无效来源。

没有有效目标的位置不能直接除以零。课程先用二值 m；若设计额外权重，需说明加权与归一化规则。

token 是编码单位，不一定是一个字或一个词

课程 byte 基线

UTF-8 字节 0–255，再加专用 BOS、EOS、PAD，共 259 个 ID。

“茶”的 UTF-8 为 E8 8C B6：一个汉字对应三个 byte token。

BPE 的一次合并

b a n a n a
选择相邻对 a n → an
得到 b an an a

这里只示意一次合并；实际实现要固定边界、频次与平局规则。

先划分训练数据，再学习 BPE 词表；检查编码解码往返。普通 byte ID 不能随意兼作 PAD。

评价前，先问测试到底独立在哪里

  • 按来源、文档或模板族划分，避免近重复内容跨集合。
  • 验证时也要满足真正预测时的信息可见性。
  • 单次低训练损失不能证明泛化，也不能单独诊断过拟合。
  • 不同 tokenizer 的 token perplexity 不能直接当成同一口径排名。
先统一数据、预测位置和分母，再比较模型。必要时在同一原始文本上，用完整序列似然换算共同的 byte 口径。
