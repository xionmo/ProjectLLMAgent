训练开始前，参数先要有一个数值起点

从零训练时，投影、FFN 和 embedding 的参数需要初始化；加载预训练模型则从 checkpoint 的参数开始。

在独立、零均值的简化条件下，输入分量方差为 1、权重方差取 1/din，可以抵消线性求和对输出方差的影响。

这解释“为什么初始化也关心尺度”；具体初始化要与激活、残差结构和训练方案一起选择。

记录初始化、数据打乱与 dropout 的随机状态。固定 seed 不自动保证不同设备或内核逐位一致。

用基础张量操作对应已学的注意力公式

假设 q/k/v 已排成 [Nb, Nh, T, dh]，这里只写等长自注意力、关闭 dropout 的核心。

T = q.size(-2)
blocked = torch.triu(torch.ones(T, T, dtype=torch.bool,
                               device=q.device), diagonal=1)
scores = (q @ k.transpose(-2, -1)) / (q.size(-1) ** 0.5)
scores = scores.masked_fill(blocked, -torch.inf)
weights = torch.softmax(scores, dim=-1)
read = weights @ v
这段代码自己的约定是 blocked=True 表示禁止。其它库接口的布尔 mask 语义要查对应版本，不能凭名字套用。

交叉注意力和带缓存的矩形形状，不能照搬这里的 T × T 遮罩。

一个 pre-LN block 的计算顺序

def block(h, blocked):
    x = h + attention(ln1(h), blocked)
    return x + ffn_gelu(ln2(x))

# ffn_gelu: Linear(d, d_ff) → GELU → Linear(d_ff, d)
# ln1、ln2、attention、ffn_gelu 分别持有自己的参数

归一化位于主路子层之前；残差旁路保留未经过这一处 LayerNorm 的输入。

这是课程初版的 block，不是把原论文 post-LN 公式原样翻译为代码。Embedding、final LayerNorm 与词表头在 block 外连接。

一次训练迭代：哪个动作真正更新了权重？

model.train()
optimizer.zero_grad(set_to_none=True)
logits = model(inputs)
loss_sum = F.cross_entropy(logits.reshape(-1, vocab_size),
    labels.reshape(-1), ignore_index=pad_id, reduction="sum")
loss = loss_sum / valid_target_count
loss.backward()
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm)
optimizer.step()

inputs/labels 已移位；先处理没有有效目标的 batch。CrossEntropyLoss 接收 raw logits，不需要先对它做 softmax。

forward 产生结果，backward 计算梯度，optimizer.step 才执行参数更新。

AdamW 还保存梯度统计，恢复训练时也要保存它们

m、v 分别追踪梯度的一阶与平方统计；偏差修正处理初始为零的影响。λ 控制独立的权重衰减项。

公式为核心逐分量更新示意。学习率、参数分组、精度与梯度裁剪等运行配置还需明确记录。

Dropout 与运行模式：为什么做核对时先关闭随机层？

设丢弃概率 0 ≤ p < 1。训练时 δ 为 1 的分量保留、为 0 的分量丢弃，并按保留概率缩放；常规 inverted dropout 在 eval 模式下直接传递输入。

model.eval()

切换 dropout 等模块的运行行为；不等于自动关闭梯度计算。

no_grad / inference_mode

控制梯度记录等执行开销；与模块的 train/eval 状态分别设置。

LayerNorm 在训练和推理中都从本次输入计算统计量。因果性、缓存和梯度累积对照应先控制随机性。

先让一个小批次学得动，再讨论泛化

设置

固定一小批无矛盾、可记忆的数据；关闭 dropout，先用 FP32 与清晰的标签规则。

观察有效位置的 loss、梯度和参数变化。

若不下降，查什么？

标签是否对齐；loss 是否连到参数；是否真的 step；梯度是否有限；学习率与容量是否合适。

这是一项实现调试，不是泛化成绩。并非所有数据或带 label smoothing 的目标都应把损失降到零。

梯度累积要对应同一个总目标

若两个 microbatch 有效 token 数分别为 10 和 90，平均 loss 分别为 1 和 3，总平均应为 2.8，不是 2。

按总有效目标数加权；累积期间不 step。全部梯度汇总之后，再裁剪、更新参数和推进相应的调度计数。

与大 batch 对照时，使用相同样本并控制随机性。浮点加法顺序不同可能产生小误差，需事先确定核对口径。

恢复训练需要的不只是模型参数

保存内容为什么需要
模型与优化器状态恢复参数和 AdamW 的 m/v 等统计。
调度器、步数与 token 计数恢复学习率与训练预算位置。
随机状态与数据采样位置使下一批数据及随机路径可核对。
代码、配置、数据版本说明此次运行究竟是什么实验。
真正的检查：不中断运行，与保存后恢复运行，下一批数据、loss 和更新是否按约定一致。

选择规则

argmax、温度、top-k、top-p 等是生成策略；需要固定配置才能比较结果。

停止规则

EOS、最大长度或任务约束决定结束。计时要记录实际生成的 token 数。

温度为正数时可对 logits 除以温度；它会改变分布集中程度，不保证改变后的概率更准确。

KV 缓存复用的是过去位置已经算出的 K、V

全前缀重算

每生成一个新 token，都重新为整个前缀做各层计算。

缓存路径

prefill 保存每层 K/V；decode 为新位置产生 Q/K/V，用新 Q 读取已有与新增 K/V。

在参数、前缀与位置不变的因果模型中，追加未来 token 不应改变过去位置的表示，这是可复用的基础。

缓存有计算图身份：换权重、换前缀或错位置，都不能继续假定旧缓存有效。

先证明同一前缀的结果一致，再比较速度

  1. 固定输入、参数、位置和精度；关闭 dropout 与梯度记录。
  2. 比较完整前缀重算与增量缓存的下一位置 logits。
  3. 核对各层缓存长度、位置编号和数值误差。
  4. 故意把位置偏移归零，检查测试是否能发现差异。
两条生成轨迹一旦已经选出不同 token，后续输入就不同了；不能再把全部差异归因于缓存。

理想算术下讨论等价；实际浮点计算按记录的容差核对。不能为让测试变绿而任意放宽容差。

KV、临时激活、工作区、分配器与服务开销。

计时先写清边界

  • GPU 操作通常异步；使用 CUDA events 或明确同步边界。
  • 先预热，区分编译、首次分配与稳态执行。
  • 分别报告 prefill、decode 和总时间，记录输入与实际输出长度。
  • 固定设备、dtype、batch、mask、内核和推理模式。
短模型、短序列的一次结果不能代表所有规模。先核对结果，再解释速度差异。
