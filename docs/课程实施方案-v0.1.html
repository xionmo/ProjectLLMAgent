《LLM 智能体的原理、系统与协作》课程实施方案

v0.1 · 2026-09-18 · 课程负责人研究与备课路线

依据：培养目标与能力标准 v0.4。本文件把已确认的目标展开为学习单元、实验顺序、资源配置与验收关卡，沿用原有深度；新增图片输入要求已同步到 v0.4。当前交付为课程设计；除另有证据的环境检查外，实验均待实施。

直接开始：第一单元教学包：U00—U03 · 实验环境与复现 · 实验报告模板

1. 先把哪条学习链走通

先用一个很小、能逐行解释的语言模型，走通“数据 → 条件概率 → 模型计算 → 训练 → 生成与缓存”；然后让它成为可以测量和修改的服务。获得稳定对象后，再研究后训练、推理预算和 Agent 系统。

课程负责人的第一轮工作顺序为：

U00—U06：建立模型与训练基线
    ↓ 同一组权重、输入和评价资产
U07—U14：追踪执行、缓存、量化、调度与传输
    ↓ 已能识别能力瓶颈与系统瓶颈
U15—U19：通过数据、后训练和推理计算改变能力
    ↓ 固定可调用、可测量的模型服务
U20—U26：上下文、harness、恢复与协作
    ↓ 形成可靠的实验环境
U27—U30：集中审计研究结论与人机学习
    ↓
U31—U33：RSI 继承对照、迁移与课程凝练

M8 的实验方法、M9 的预测与独立答辩从 U00 就开始。

这是推进依赖，不是要求把一整块学完才接触另一块。U00 用一条合成工具轨迹建立全景，U03 提前引出 KV，U07—U14 深入系统；到 U19 再联合比较训练与推理预算。U27—U30 是深化审计，前面各单元已必须执行相应研究规范。

本轮以个人研究式学习为单位；正式课时、学分和学期编排在复现与试教后确定。以下 U00—U33 共 34 个基础单元，加上插入其中的 V01—V06 图片输入单元，合计 40 个单元。各自包含讲解、实践和答辩，可以分多次学习完成，不等于 40 次课堂课。

2. 本机条件与可执行范围

本地只读检查确认 RTX 4090，24564 MiB 显存、计算能力 8.9、驱动 616.56。WSL 可见内存约 23 GiB，Windows 物理内存约 31.9 GiB；两者不可直接当作同一可用容量。已查询到 GPU，不代表 PyTorch 或推理引擎已经验证通过。

课程目录在共享存储：Windows 的 Z 盘与 WSL 的 /mnt/Projects 指向同一位置。代码、文档和归档留在项目；正式训练前选定本机热数据目录，分别测本地与共享存储的加载时间，再决定数据缓存位置。不要把共享文件系统 I/O 混入 GPU 性能结论。

实验层级 首选规模与工作 本机怎样完成 结果边界
D0 计算正确性 2 层、宽度 64、短序列、FP32 CPU 或单卡；固定输入，检查梯度、mask、缓存 解释数值机制，不评价语言能力
D1 从零构建 4 层、宽度 256、4 个头、FFN 1024、byte tokenizer、上下文 256—512 约 3—4M 参数，实际由代码计数；逐步增大 microbatch 先完成可解释的训练与恢复；规模不是达标标准
D2 架构与数据对照 约 30—100M 参数；同一数据协议 先测 100 步的显存与设备时间，再定 token 预算 不把小模型结果直接外推到前沿模型
D3 开放权重迁移 首先选择 0.5—3B 的兼容模型；7—8B 为后续候选 检查许可、tokenizer、普通全注意力或混合状态、引擎支持与实际内存 模型家族与 revision 在实施前锁定，不以“最新”作选择标准
D4 后训练 小模型全参数训练；较大模型优先考虑 LoRA 等可控方案 由激活、序列长度和优化器实测决定配置 不能只按权重大小判断是否可训练
D5 推理系统 单 GPU 的缓存、调度、量化、负载、跨进程传输 深入一套真实引擎，再定点比较第二套 单卡并发、进程通信不构成多 GPU 加速证据
D6 扩展验证 Blackwell 原生 NVFP4；多 GPU/多机 TP、PP、EP 或 PD 分离 到达对应研究问题时追加设备实验 没有设备时标记“待真实硬件验证”，保留 L3/L4 缺口

本轮默认先读通 vLLM 的请求、调度与 KV 路径；SGLang 用于前缀复用、分层缓存等设计的定点比较。这是减少并行学习负担的教学选择，不是性能排名。安装前锁定兼容的驱动、Python、PyTorch、CUDA wheel 与引擎版本；训练环境和服务环境分别建环境、分别保存依赖清单。

2.1 4090 上怎样安排 NVFP4

NVFP4 专题分成三个可独立验收的层次：

  1. **数值层：**实现 E2M1 取值、16 值分块、E4M3 块缩放和张量缩放的参考路径，核对舍入、全零块、异常值、打包和实际字节数。
  2. **本机执行层：**依据具体软件版本核查可用的 weight-only / Marlin 路径，与已验证的 BF16 或 INT4 路径比较；记录实际内核及反量化发生位置。可加载某格式不意味着使用原生 FP4 矩阵乘。
  3. **硬件迁移层：**在支持的 Blackwell 设备上验证原生 NVFP4。预先固定模型、校准集、输入形状和质量口径，再比较差异；设备不同也改变带宽、容量和计算能力，不能把全部收益归因于格式。

NVIDIA 的格式说明将原生 NVFP4 与 Blackwell Tensor Core 联系起来；vLLM 当前兼容表列有 Ada 上的 Marlin FP4 路径。二者描述不同执行条件。本机是否满足某模型的量化组合仍要实测。NVIDIA 格式说明 · vLLM 量化兼容表

2.2 预算如何确定

先用短预实验测成本，再定正式预算。第一轮建议每个候选先跑 100 步或一个小负载批次；这用于发现 OOM、数据错误和数量级问题，不用于宣称算法优劣。

每次正式实验预先选一个主资源约束：实际训练 token、估算 FLOPs、GPU 设备时间或端到端预算，同时报告其他可观测投入。相同训练步数、相同生成 token 数或相同实验轮数不能自动视为等成本。

单卡训练与服务性能测量分时运行。记录其他 GPU 使用、功耗状态、冷暖缓存、编译和预热；做配对或随机交错测量，避免把时段变化当成干预效果。正式规模由预实验决定，不承诺尚未测得的吞吐或耗时。

4. 两项旗舰共享哪些资产

4.1 旗舰 A：可解释的模型与能力塑造

保留三种角色明确的模型：手写教学模型、从零训练的研究模型、开放权重迁移模型。前两者可以共用实现；第三者用于检查尺度和真实模型行为。

教学模型先采用 byte 编码，消除词表训练与外部下载的先修依赖；U01 单独实现小型 BPE 并比较编码效率。后续预训练再选定 tokenizer。Tokenizer 改变后，重新建立 token 预算和评价口径，不复用原来的 perplexity 排名。

任务资产使用公开可用数据或全新生成环境，分为：

  • 建模语料：检验 next-token 学习与数据配比。
  • 可验证任务：受限算术、字符串变换、小型状态机或可执行程序；每题有独立结果判定。
  • 迁移任务：留出的长度、组合、模板家族或不同语料来源。

样本、生成器和切分规则都冻结版本。模板变体与共享来源分组切分；使用新 seed 不保证任务分布独立。

4.2 旗舰 B：模型服务与资源约束

先写最小 runner，建立正确性基线；再接真实引擎。手写模型接入真实引擎前，需要验证架构配置、权重映射、tokenizer 与 logits 等价；适配器尚未完成时，明确使用另一个受支持模型开展引擎实验。

共同负载定义建议从 3 × 3 小矩阵开始：短/中/长输入 × 单请求/中并发/高负载。实际 token 档位与到达率由 U07 的容量预实验确定。比较缓存时另加重复前缀与无共享前缀两组；量化校准集与质量测试集分离。

同时记录服务层的 TTFT、TPOT、延迟分布、token 吞吐和任务层的质量、完成时间与总成本。TPOT 的定义、流式 chunk 与 token 的关系、是否含排队必须写清。样本不足时展示原始分布，不报有误导性的 p99。

4.3 联合研究如何避免混杂

先固定权重研究系统，再固定系统研究训练；两边分别完成后做交叉实验。若同时修改模型、量化、提示与调度，必须增加必要消融，不能只凭最终分数给某个机制归功。

图片分支另保留源图哈希、源图组、processor 版本、处理尺寸、视觉 token 与图文配对记录。图片真值与模型输入隔离，模型修改后同时检查文字能力。

训练数据、任务环境、模型快照、服务配置和评价器使用相互关联的版本标识。原始日志与失败候选保留；实验集一旦用于反复选方案，就标为开发集。

7. 每次课的固定教学结构

  1. **先预测：**给一个有歧义的现象，记录解释、数量级和信心。
  2. **重建机制：**推导关键计算，跟踪张量或状态；标出假设。
  3. **读原始证据：**看论文中的一个关键实验或库中的一条执行路径。
  4. **做区分性实验：**用基线、单因素干预与故障负例区分解释。
  5. **换条件：**换长度、任务、模型或负载，检查解释还能否成立。
  6. **独立答辩：**关闭 AI 帮助，解释一段实现或诊断新故障。
  7. **沉淀教学卡：**记录可复现步骤、失败案例与下一问题。

允许 AI 参与实现、推导讨论和文献梳理；个人必须能核对来源，解释代码，并在陌生条件下重新判断。运行成功、答案流畅和研究结论可信分别验收。
