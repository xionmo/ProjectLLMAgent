本文件定义培养目标、知识边界、实践深度和达标证据。当前首先服务于课程负责人的系统学习与研究；正式学时、学分、授课顺序和学生工作量，根据实际复现与试教再确定。所有新安排的实验均为待实施设计，文中没有宣称已经取得实验结果。课程负责人已在其他项目中完成的 KCS 实践单独记录，不重复安排为实验。

本版对齐：M1—M9 全部进入 L3—L4 深度；旗舰实验集中于 M1—M4 的 LLM 构建、训练、推理与服务；以训练或服务研究流程的递归改进作为 RSI 概念实验；上下文压缩保留为专题实验。

1. 培养使命与项目定位

1.1 培养使命

面对陌生领域中的真实任务，能够建立任务与评价标准，联合设计模型、数据、harness、工具环境和推理服务；能够沿着系统各层定位问题，通过可复现实验改进表现，并解释方案的适用条件、代价与局限。

培养对象应同时具备端到端交付能力、机制理解、研究判断与知识迁移能力。模型与服务层的核心画像是：能够从实现与测量出发，解释一种能力怎样被训练出来、怎样在有限资源下被可靠调用，以及改进为什么成立。FDE 在本文指深入业务现场、承担端到端交付的工程师，其任务定义和交付能力是本课程画像的一部分。

1.2 已对齐的建设原则

  1. 正式课程名采用《LLM 智能体的原理、系统与协作》。
  2. 课程负责人先深入各个知识板块，再决定教学取舍；不先用一学期限制学习范围。
  3. 教育目标是 AI 全栈通才与方向专才的结合。M1—M9 均按 L3—L4 深度建设：各模块完成独立研究式掌握，并推进可检验的研究问题。方向专精体现为贡献的持续性与深度。
  4. 重要历史技术节点应学习其问题背景、机制和适用边界，必要时安排复现与迁移实验。
  5. 心理学、神经科学、社会学、组织研究和教育学通过具体问题与证据进入课程。
  6. QuantML 保持独立运行，作为可选案例。主学习路线覆盖软件、知识服务、科研及其他领域。
  7. 课程材料逐步沉淀为知识节点、原始文献、最小实现、实验记录、反例和教学说明。
  8. 旗舰实验以 LLM building and serving 为重心，由模型与数据到训练、推理能力和服务系统形成连续证据；M5—M9 保持同等深度要求，承担独立研究和跨层验证。

1.3 最终应能完成的工作

毕业者应能接手一个信息不完整、预算有限、会出现失败的任务环境，完成需求澄清、基线建立、模型与系统选型、实现、评价、交接和后续改进。他应能回答：

  • 哪一类任务值得引入模型决策，哪些步骤已有可靠的确定性实现？
  • 一个失败主要来自能力不足、信息不足、状态错误、工具接口、资源约束，还是评价方式？
  • 增加模型能力、推理计算、检索、训练数据或 Agent 数量，哪项干预最值得先试？
  • 一项改进换到不同任务、模型、数据分布或硬件条件后，为什么可能失效？
  • 人承担了哪些判断与补救工作，这些投入是否已经计入系统成本？

2. 共同语言与证据边界

2.1 关键对象

对象 本课程采用的工作定义 需要辨认的边界
语言模型 通过参数化计算，在给定条件下产生 token 分布的模型；多模态模型还接受其他形式的输入表示 模型权重、推理状态、外部知识与运行时逻辑属于不同对象
Agent 围绕目标，在环境中反复观察、选择行动、获取反馈并更新工作状态的系统 自动运行不自动意味着具有模型驱动的自主决策
Workflow 对任务步骤、依赖关系和控制流程的组织 预定流程与动态决策可以组合使用
Agent harness 将模型组织成可运行 Agent 的系统，包括上下文准备、工具执行、状态、事件、资源控制和结果处理 应能区分复用现成运行时、增加业务编排、修改运行时内部机制
推理服务 装载模型并执行、调度生成请求的服务系统 与业务层任务规划、长期记忆和验收逻辑分别建模
上下文 一次模型计算实际获得的信息及其表示 硬盘上存在的文件不一定已经进入上下文
持久记忆 跨调用或跨会话保存、选择、更新并再次使用的信息 必须说明写入、检索、时效、冲突、更正与删除机制
轨迹 一次任务执行中可记录的观察、输出、工具调用、反馈与状态变化 可见推理文本不等于可直接观测全部内部计算机制

上述术语用于统一课程中的系统边界。Agent 与 workflow 可参考 Building effective agents；harness、轨迹与环境最终状态的区分可参考 Demystifying evals for AI agents。

2.2 “压缩”的四个维度

讨论压缩时，必须同时写明压缩对象、算法、执行位置和保真标准。

操作 作用对象 常见产物或结果 必须检验什么
会话 compaction 消息、工具结果及会话状态的表示 摘要、保留消息或服务商定义的压缩项 后续行动是否保留必要约束与信息
结构化 handoff 任务目标、事实、进度、决策、未完成项 可阅读、可版本化的交接材料 下一会话能否恢复真实工作状态
持久记忆提取 可跨任务复用的经验或事实 文件、数据库记录、检索条目等 来源、适用范围、时效与更新正确性
KV 量化或裁剪 注意力推理状态中的数值或条目 更低精度或更少的缓存状态 数值与任务质量变化、长程依赖损失
前缀缓存复用 已计算的相同兼容前缀状态 避免重复 prefill 命中条件、兼容性、冷暖缓存差异
分层存储与迁移 缓存所处介质和位置 GPU、主存与存储后端之间的数据移动 传输与重计算代价、命中率和延迟

“本地压缩”在本文不作为独立算法名。应使用“客户端管理的会话摘要”“本地保存的 handoff”“服务端执行的压缩”等具体表述。客户端触发、文件在本地保存、模型在本机推理，是三个独立属性。

Claude Code 的公开文档描述了清理旧工具输出、必要时摘要会话的上下文管理，以及 /compact 的定向摘要用途。持久记忆文件有独立的加载和维护机制。因此，/compact 不能直接等同于创建一套 handoff 文档或长期记忆。Claude Code 工作原理，Claude Code 记忆机制

OpenAI 的公开 compaction 接口提供不供人直接解释的加密压缩项。接口行为可以被测试，其未公开的内部实现不能被当成已知的 token 删除、普通摘要或 KV 裁剪算法。OpenAI Compaction

2.3 自改进与 RSI

RSI 在本文按 Recursive Self-Improvement 理解。相关研究的用法并不完全统一，本课程采用以下操作性分类，而不以一个标签代替实验说明。

被改变的对象 可能的改进方式 应报告的事实
知识库、记忆 增补事实、重构条目、修正过期知识 哪些外部资产改变，依据来自哪里
Prompt、工具、harness 修改接口、提示、控制逻辑、检查器 哪些运行策略改变，版本与验证结果
模型参数 微调、蒸馏、偏好学习、强化学习 数据、目标、更新过程与退化情况
改进过程本身 修改任务生成、搜索、训练或改进策略 新过程能否在独立条件下产生更有效的后续改进

自改进可以发生在模型权重之外。若使用“递归”一词，应明确改进结果如何反馈到未来的改进过程，并检验多轮效果；不能从单次收益推断无限持续进步。

本版新增阅读 The Last AI Built by Humans: Toward Genuine Recursive Self-Improvement（用户提供的 v1）。这是一篇综述与框架性预印本；本课程采用它对“改进机制被继承并实际使用”和“继承后更有效地产生后续改进”的区分。论文的 RSI 自主性 L1—L5 与本课程描述人的学习深度 L0—L4 属于两套坐标，引用时分别写作“RSI 自主性”和“课程深度”。第 9 节是据此提出的课程实验设计，尚无实验结果。

两个不同的公开参照是：通过修改 Agent 代码并执行基准检验的 Darwin Gödel Machine，以及让模型生成适配数据和更新指令、再评价更新后表现的 SEAL。这些工作支持研究路线的可行性，不直接验证本项目听闻的具体业务案例。

2.4 证据等级

所有讲义和研究报告应区分：已验证的实现事实、论文在其设置下报告的结果、工程经验、类比、待检验假设。模型卡中的分数、演示和内部传闻不能自动升级为跨场景结论。

人脑、组织和教学类比必须分别说明功能层、算法层和实现层的对应关系。语言表现、任务能力与解释忠实性应单独评价。语言与思维的区分，推理文本的忠实性研究

3.2 深度等级

等级 能力表现 典型证据
L0：辨认 能辨认对象和术语，指出未知部分 概念图与问题清单
L1：使用 能按文档运行、改变配置并描述结果 可重复的使用记录
L2：重建 能解释机制、实现缩小版本、预测局部变化 推导、最小实现、预测与测量
L3：研究式掌握 能独立比较方案、诊断失败并检验迁移 对照与消融、原始数据、边界分析
L4：研究贡献 能提出并检验新的机制、方法或适用边界 有贡献的问题定义、可靠研究结果及可复现材料

L4 可以体现为有价值的阴性结果、反例或评价方法，不以刷新榜单或论文录用为必要条件。

统一深度目标：M1—M9 全部达到 L3，并在每个模块推进 L4 研究训练。 每个模块均须完成机制重建、受控比较、失败诊断与陌生条件迁移；随后至少推进一个有明确贡献空间的问题，完成文献差距、假设、区分性实验和结论。课程负责人先沿此标准走通，后续学生路线也以此为目标，不预设某些模块只需停留在 L1—L2。

“安排到 L4”意味着提供研究问题、方法指导、实验资源和答辩要求；是否已经达到 L4，取决于实际贡献与证据。新问题经研究后可能只得到已有结论的复现，此时应如实记为 L3；有价值且论证充分的反例或阴性结果可以达到 L4。

一个跨层项目可以支撑多个模块，但须逐项标出各模块的独立问题、干预和证据。不要求每个模块单独发表一篇论文，也不能用某一专精模块的贡献抵扣其他模块的掌握。正式教学可分阶段或连续研究项目实施，学时与资源依据试教确定。

3.3 评价维度

每个实践成果分别评价六个维度：机制理解、实现与可复现性、实验有效性、资源判断、迁移与局限、个人理解与沟通。使用上述 L0—L4 描述，保留维度分布，不用一个平均分隐藏关键短板。

共享验收要求：结论与证据一致；他人能按说明复现主要结果；保留失败运行；区分观察与推测；能解释关键实现。依赖泄漏评测、无法核对的结果或未说明的人工补救，不构成对应能力的达标证据。

M4 推理服务与硬件 建立容量与性能模型；实现缓存/调度干预和量化；用剖析解释瓶颈，跨负载核验预测 模型精度、状态布局或调度机制的共同设计，能否在质量与时限约束下提高有效吞吐？
M5 上下文与记忆 实现可追溯上下文流程；比较摘要、handoff、检索等基线；检验目标改变和多次恢复 信息选择与检索策略在目标漂移下有哪些保真边界，能否据此设计更稳健的状态表示？
M6 Harness 与执行 读通并修改关键运行路径；以故障注入验证状态、幂等、恢复和完成条件，迁移到不同工具 状态协议或恢复机制如何减少长任务中隐藏的重复副作用、错误完成和恢复成本？
M7 多 Agent 协作 对比单 Agent、固定流程和协作结构；分析依赖、相关错误、关键路径与通信，解释收益条件 能否根据任务结构与可观测运行信号选择分工和模型，并在陌生任务族上保持收益？
M8 评测与研究方法 建立隔离评测；处理相关样本、择优偏差和预算；独立复核一项收益并给出反例 自适应研究反复使用反馈时，怎样检测评测过拟合并可靠估计真实进步？
M9 人、组织与学习 设计人机分工及同伴教学的受控比较；计入人工贡献，检验校准、独立判断和延后迁移 哪种反馈与任务安排促进技术直觉和独立能力，哪些条件下增加依赖或错误共识？

各模块的 L4 研究可以形成同一条证据链。例如，M2 改变训练轨迹，M3 解释推理预算收益，M4 检验服务代价，M8 检查提升是否来自评测偏差；每一环均需有自己的可否证问题。

M1. 语言模型的能力从哪里来

必须能解释： 分词与编码、条件概率分解、embedding、因果注意力、位置表示、残差与归一化、前馈网络、训练目标与生成。区分 encoder、decoder 和 encoder-decoder；理解 Dense、MoE、MHA/MQA/GQA、潜在状态和混合架构的设计空间。区分总参数、激活参数、计算量与驻留内存。

必须亲手复现： 用 PyTorch 构建可训练的小型自回归语言模型；明确训练所用目标、掩码与张量形状；核对一段前向计算或梯度；实现有缓存和无缓存的生成并检查数值误差。至少做一项架构改变，在明确的训练或推理预算下比较；以相同数据切分和可核对的优化条件排除混杂，检验一个陌生长度或任务条件。

必须实际测量： 训练与留出损失、任务表现、参数量、内存、生成速度；在改变长度、数据或架构时记录预测与实测偏差。跨 tokenizer 比较时，说明 token 口径差异，不能直接用不同 token 定义下的 perplexity 排名。

L4 研究方向： 表示、归纳偏置、模块化、稀疏路由、长程依赖和状态压缩如何共同影响任务能力。多模态与具身方向扩展输入表示和行动空间，沿用相同的机制与评价要求。

L3 达标证据： 可运行模型、关键推导、至少一个受控改变及反例、从模型配置到资源估算的说明。原始入口：Transformer、Switch Transformer、GQA。

M2. 数据与能力塑造

必须能解释： 预训练、继续预训练、SFT、参数高效微调、蒸馏、偏好学习、强化学习、可验证奖励；策略、奖励、信用分配和分布偏移。理解数据清洗、去重、混合、来源、难度、多样性与污染；区分教师输出模仿、可获得 logits 时的分布蒸馏，以及学生自身轨迹上的纠正。

训练系统部分覆盖数据加载与序列打包、优化器、混合精度、梯度累积、激活重计算、梯度同步与状态分片。能够分开估算权重、梯度、优化器状态和训练激活，并说明它们与推理 KV 的区别；通过小规模实验理解有效批次、数值误差、通信和训练效率的关系。

必须亲手复现： 完成小模型预训练；建立任务资产到合成数据的流程；在一个真实工具接口或可执行模拟环境中生成并验证轨迹；完成一次 SFT/蒸馏实验，并完成一种偏好或奖励驱动更新的受控比较。保留基础模型、检索或提示改进的对照。训练中正确处理工具观察、模型输出和 loss mask。

必须实际测量： 数据通过率、去重与来源覆盖、教师和验证开销、学习曲线、留出任务表现、通用能力退化、校准变化；报告训练和推理的总投入。失败或不充分的轨迹不能仅凭语言流畅度进入“正确示范”。

L4 研究方向： 合成任务的覆盖与真实分布错配；教师错误传播；学生自己遇到的状态与教师轨迹之间的差异；训练数据、工具协议和 harness 的共同适配；主动索取 human knowledge delta 的策略。

L3 达标证据： 可追溯数据、生成与验证代码、训练配置、独立评测、退化分析。原始入口：Chinchilla、Self-Instruct、DPO、DeepSeek-R1、SWE-smith。

M3. 推理、规划与验证

必须能解释： 推理时计算、串行展开、并行采样、候选选择、搜索、规划、重新规划、工具反馈、过程验证和结果验证。区分单次推理质量、搜索覆盖、选择器质量和最终任务完成率。

必须亲手复现： 为同一批可验证任务比较直接生成、分步求解、多候选与验证、带环境反馈的工具循环。选择一个必须根据中间观察改变计划的任务，记录状态和决策。

必须实际测量： 成功率、额外采样收益、选择器误判、工具与生成成本、总时长、错误恢复；分别在相同预算和相同质量要求下比较。不能把拥有正确答案 oracle 的 pass@k 当成可部署选择策略的成功率。

L4 研究方向： 自适应分配计算、验证器与生成器的相关错误、可见推理解释的忠实性、不可完全观察环境下的计划与停止条件。

L3 达标证据： 受控任务集、完整轨迹、验证器独立性说明、预算对照与失败类型。入口：ReAct、推理忠实性。

M4. 推理服务、硬件与量化

必须能解释： prefill/decode、连续批处理、分块 prefill、前缀复用、KV 分配、推测解码、PD 分离；数据、张量、流水线与专家并行；算力、带宽、排队、通信和负载分布。理解 vLLM、SGLang 的模型执行、调度、缓存和扩展接口，而非只记启动参数。

硬件部分覆盖 GPU 芯片内 SRAM、HBM/GDDR 显存、DDR 主存、SSD 与 NVMe 接口，以及 PCIe、GPU 间互连与跨机网络；能够用算术强度、带宽与计算上限解释性能，并用剖析核对。具体容量、带宽、精度与内核支持以实验硬件和版本为准。

参数至少分三组：采样行为参数（temperature、top-k、top-p、停止条件等）；引擎执行与调度参数（批次与 token 预算、并发、分块和缓存等）；模型、精度与部署参数。输出长度、上下文长度和推理预算可能同时影响多项质量与性能指标。

量化部分覆盖训练后量化与量化感知训练，权重、激活、KV 的分别量化，校准、异常值、分组、缩放与混合精度。区分压缩后的存储体积、实际工作内存、内核支持及端到端加速。

必须亲手复现： 在单机运行一个开源推理引擎并读通一条请求路径；构造长度、到达率与并发受控的负载；实施一种缓存或调度干预和一种量化实验；至少运行一次可核对的跨进程并行或传输实验。多机条件可后续扩展，模拟通信不能被报告为真实集群收益。

必须实际测量： TTFT、逐 token 间隔或 TPOT、端到端时长、p50/p95/p99、吞吐、满足质量与时限的有效吞吐、显存、主存、缓存命中率、传输量、任务质量。区分冷启动、冷缓存和暖缓存，说明测量是否含排队及工具等待。

对于各层 KV 配置相同的普通全注意力 MHA/GQA，初步 KV 容量估算为：

KV_bytes ≈ 2 × 层数 × 各请求缓存 token 数之和 × KV头数 × 头维度 × 每元素字节数
运行内存 ≈ 实际驻留权重 + KV或其他推理状态 + 临时激活与工作区 + 框架开销

该 KV 公式不直接适用于所有 MLA、滑动窗口、混合或循环状态架构；也未包含分页浪费、元数据与并行复制等。学习者必须按实际模型修正估算，并核对测量。

L4 研究方向： 量化校准与 Agent 工作负载适配、缓存迁移和重计算的盈亏条件、PD 分离的部署条件、混合架构的状态管理、服务端调度与上层任务规划的共同优化。

L3 达标证据： 容量模型、负载生成器、配置矩阵、性能曲线、质量对照、预测偏差分析。技术入口：FlashAttention、PagedAttention、AWQ。实现入口：vLLM PD 分离、SGLang HiCache。

M5. 上下文、知识与记忆

必须能解释： 上下文构建、指令与证据来源、工具结果筛选、检索、重排、摘要、压缩、持久记忆、时效和冲突处理。区分会话记录、当前上下文、外部知识、任务状态与模型推理缓存。

必须亲手复现： 构建一个可追溯的上下文准备流程；比较完整历史、截断、普通摘要、结构化 handoff 和目标相关压缩；实现跨会话恢复与记忆更正。记录哪些信息是保留、重新检索、重新计算或已经丢失。

必须实际测量： 下游任务表现、关键状态保留、来源正确性、上下文占用、压缩与检索开销、跨多次压缩的退化、目标变化后的恢复能力。

L4 研究方向： 预算约束下的信息选择、目标变化时的记忆策略、压缩与检索的协同、语义压缩与 KV 近似的交互、从使用反馈维护知识。

L3 达标证据： 上下文与状态模式、可重放任务、压缩对照、信息丢失案例和成本分析。入口：Context engineering。该项为专题实验，完整方案保留于附录 A。

M6. 单 Agent、工具与 harness

必须能解释： 工具契约、状态转换、事件、观察与行动、超时、取消、重试、幂等、检查点、恢复、任务完成判定、权限与隔离。理解哪些边界由程序和环境执行，哪些只是模型可见的指令。

必须亲手复现： 实现一个最小工具循环；为一个成熟 harness 编写业务适配；读通其任务到工具结果再到下一次模型调用的路径；注入进程中断、工具超时、重复调用、部分完成与状态过期等故障。

必须实际测量： 完成率、恢复成功率、重复副作用、错误完成声明、人工介入、总时间和资源开销；核对外部结果，而非只读 Agent 的自述。

L4 研究方向： 运行状态与自然语言计划的一致性、长任务恢复、完成条件的组合、不同模型与运行时协议适配、环境设计如何改变模型能力表现。

L3 达标证据： 架构与接口说明、状态与事件记录、故障实验、可验证的完成条件。现成运行时入口：Codex App Server。长期任务案例：Effective harnesses。

M7. 多 Agent 与组织设计

必须能解释： 任务分解、依赖、关键路径、协调方式、角色与工具权限、共享和独立上下文、通信、结果合并、冲突与相关错误。多个角色名不自动产生独立知识或互补能力。

必须亲手复现： 比较单 Agent、固定流程和至少一种多 Agent 结构；在可分解任务与强顺序依赖任务上分别测试；固定工具与评价条件，另设预算匹配对照。

必须实际测量： 质量、总计算量、关键路径时间、通信与协调开销、重复工作、合并错误、验证者漏检、人工调度成本。

L4 研究方向： 按任务难度路由模型、异构模型分工、动态委派、团队记忆、证据独立性、架构与任务结构匹配。

L3 达标证据： 依赖与通信图、单 Agent 基线、至少一种收益不足或失败条件，以及有依据的模型分配策略。受控比较入口：Towards a Science of Scaling Agent Systems。

M8. 评测、安全、可靠性与研究方法

必须能解释： 任务分布、构念与代理指标、留出和时间划分、污染、重复试验、相关样本、置信区间、多次择优、评价者偏差、版本漂移。理解提示注入、工具越权、状态泄漏、反馈或奖励被利用的失败机制。

必须亲手复现： 构建可重放评测环境；组合程序判定、环境状态核对与经校准的人评/模型评；注入受控故障和不可信输入；把一项宣称的提升拆解为可检验的因果干预。

必须实际测量： 任务质量及分层错误、评测者一致性、重复运行波动、成本、人工投入、恢复与边界行为。结果解释应明确样本与任务覆盖范围，观测到零次错误不等于普遍安全。

L4 研究方向： 长程 Agent 评价、隐藏失败、评测器稳健性、知识演化中的自证循环、模型与 harness 更新的回归检测。

L3 达标证据： 评测说明、隔离的开发与审计资产、原始运行记录、统计与成本报告、未解决问题。入口：Agent evals、LLM-as-a-judge 偏差。

M9. 人、认知、组织与学习

必须能解释： 语言表现与任务能力、解释与证据、认知卸载、元认知、信任校准、专业直觉、分工责任、交接、反馈、教学支架与迁移。神经科学部分学习证据和研究方法，明确类比不自动构成同机制结论。

必须亲手复现： 在模型构建、系统诊断或 Agent 任务中设计人机分工实验；记录真实的人工假设、补充、审核与纠错；开展一次面向同伴的教学，并通过陌生问题或延后任务检验理解迁移。课程负责人已完成的 KCS 项目作为既有案例，待演讲稿提供后可提取相关证据，不重复安排该实验。

必须实际测量： 人工时间、介入时机、错误升级、知识更新正确性、任务结果、学习者独立解释与迁移能力。参与者研究按机构实际要求实施，避免把同一人的重复任务误当独立样本。

L4 研究方向： AI 辅助模型研究中的独立判断与技能形成、研究团队的错误共识、自动实验与人类审核的分工、技术直觉的反馈条件、教学效果向新任务的迁移。

L3 达标证据： 人机协议、人工投入记录、预测与反思日志、个人答辩、可验证的教学效果。直觉研究入口：Conditions for intuitive expertise。知识组织入口：KCS Double Loop。

8.1 旗舰 A：从零构建并塑造一个可研究的语言模型

核心模块：M1、M2、M3；组成实验：E02—E04。

核心问题：在可核对的训练与推理预算下，架构、数据、学习目标和推理策略各自改变了什么能力，在哪些条件下可以相互替代，在哪些条件下不能？

采用两个实验尺度：用从零训练的小模型重建完整机制与受控变化；用兼容的开放权重模型检验部分观察是否迁移。两者分别报告，不把小模型结论直接外推到前沿模型。小模型可采用受控语言、算法或工具任务，使正确性可验证；任务的受限性质须明确。

阶段 必须实施的工作 必须留下的证据
构建 数据切分、tokenizer、因果模型、训练循环、优化与检查点；核对掩码、梯度、数值稳定性和恢复；测量一种训练内存或执行优化 张量与计算说明、数值核对、训练内存账、可复现基线、异常训练诊断
预训练 固定数据处理与评价，改变至少一个架构因素；比较数据规模或配比的影响 学习曲线、实际 token 与设备时间、受控架构/数据对照
能力塑造 构造并验证训练轨迹；完成 SFT/蒸馏及一种偏好或奖励驱动更新；保留未更新和等成本数据对照 数据来源与质量、loss mask、教师/验证成本、能力收益与退化
推理与验证 在同一检查点比较直接生成、多候选、可部署验证/选择和环境反馈 成功率、选择器误判、推理预算曲线、完整失败轨迹

不要求同时遍历全部架构和训练算法。先建立稳定的主基线，再围绕一个可辨认的机制安排实验；各阶段使用的检查点与训练历史保持可追溯。

必要对照。 架构比较说明匹配的是参数、训练 FLOPs、设备时间还是部署成本；不能只用相同训练步数声称公平。后训练比较区分增加信息、增加训练计算与改变学习目标。研究训练和推理计算的关系时，至少在两个后训练配置和两个推理预算间作交叉比较；其余无关因素保持一致。不同 tokenizer 的指标需统一口径。

主要结果。 同时报告留出建模指标、任务质量、泛化、旧能力退化，以及数据生成、训练、验证与部署推理的投入。训练损失改善、解释文本变长、验证器分数上升均不能单独替代真实任务改善。

L3 验收。 能重建整条链路，解释至少一个有效干预和一个失败条件，并用独立任务核验解释。L4 入口。 可研究学生失败驱动的数据选择、结构归纳偏置与数据配比、训练与推理计算的分配，或验证器误差下的能力塑造；贡献需超出对现有配方的照搬，并经文献和独立实验核对。

8.2 旗舰 B：构建并解释一个受资源约束的 LLM 推理服务

核心模块：M1、M3、M4；组成实验：E05—E06。

核心问题：给定模型质量要求、硬件和请求分布，如何找到容量与性能瓶颈，并用可解释的机制改善质量—时延—成本关系？

从旗舰 A 的可兼容检查点接入服务，再选一个有代表性的开放权重模型检查系统现象的尺度依赖。先在 vLLM 或 SGLang 中深入一套引擎：读通请求、调度、模型执行、状态存储与结果返回的路径；再对另一套引擎的对应设计进行定点比较。只有实验条件一致时才比较性能。

工作包 必须实施的工作 关键判据
容量与瓶颈模型 估算权重、KV/其他状态、临时空间；分析计算、显存带宽、传输与排队 预测与剖析是否一致，偏差能否被解释
执行与缓存 实现一个最小缓存/调度机制；在真实引擎中修改一处对应机制或扩展接口 计算正确性、状态生命周期、内存占用与端到端影响
量化 实施一种权重量化，另比较一种激活或 KV 精度方案；保留高精度参照与校准集隔离 质量损失、实际驻留内存、内核兼容性与可测加速
负载与调度 控制到达率、输入/输出长度、前缀复用和并发；比较至少一种调度干预 冷暖缓存、排队、长短请求干扰、取消和恢复
并行与传输 在可用设备上测量跨进程通信；具备多 GPU 时比较一个并行或 PD 方案 通信/搬运与重计算的盈亏条件，单机与多机结论分开

内核可用性和硬件限制属于实验条件。如果某精度格式只有仿真实现，应分别报告数值影响和真实性能；不能将位宽比例当作加速倍数。多 GPU 或多机结果必须实际测量，缺少设备时保留待验证问题及容量分析。

比较顺序。 先固定模型和质量条件分析一个瓶颈，再引入联合优化。研究交互时，可选择“权重精度 × KV 精度”“缓存策略 × 调度策略”或“模型大小 × 推理预算”等因子设计，避免同时改变所有组件后无法解释收益。PD 分离、分层缓存和更大并行度均需通过负载与通信条件解释收益范围。

主要结果。 绘制 TTFT、TPOT、端到端时延及其分位数随负载变化的曲线，报告满足质量与时限的有效吞吐、OOM/超时/取消、实际内存和总成本。采用外部到达过程的负载用于观察饱和与排队；固定并发负载另行标记，避免将客户端等待造成的吞吐下降误读为服务稳定。失败请求进入分母。

L3 验收。 至少完成一个“预测瓶颈—剖析—实现干预—对照—跨负载验证”的闭环，并解释优化失效或变差的条件。L4 入口。 可研究质量约束下的量化校准、状态管理、调度或模型—服务共同设计，以可复现的性能边界、新机制或有价值的反例形成贡献。

8.3 两项旗舰的联合验收

最终提交一张由真实测量得到的质量—训练投入—推理成本—时延关系图或表，展示至少两个可行方案及其适用负载。说明哪项收益来自模型能力，哪项来自搜索与选择，哪项来自执行效率。

资源缩放须保留问题结构：减少模型规模、数据或实验因子可以降低成本，仍须保留基线、机制干预、独立评价和迁移。两项旗舰的结果为第 9 节提供研究对象与基线。完整 Agent 应用负责检验这些结果能否迁移到实际工作流。

9. RSI 概念实验 E10：让训练或服务研究流程改进自身

9.1 定位与研究问题

本实验接替原 KCS 实验的位置，在旗舰 A 或 B 的成熟环境中实施。它研究一个受控、可观测的递归改进机制，实际达到的自主范围与效果由证据判定。无需预设系统能够无限进步。

研究问题：一个研究 Agent 改写并继承自身的实验选择或改进策略后，能否比固定改进器在相同总预算下，更有效地改进新的模型训练任务或服务配置？

与本课程底层主线相关的原始案例是 A-Evolve-Training v3：作者报告了自动化模型后训练，并通过跨轮研究策略调整组织后续实验。本课程从可复现的小规模环境起步，不将其模型规模或报告成绩设为本实验门槛。

9.2 两层对象与可修改范围

对象 实验中可以改变的部分 本轮保持固定的条件
被改进的模型或服务 S 选择训练分支：数据生成/选择、配比、后训练配方；或服务分支：量化校准、调度策略、可测的实现片段 任务定义、资源约束、输入输出契约与外部验收
改进器 I 提出假设、选择下一实验、分配试验预算、解释失败及更新候选的策略；可表现为程序或可执行的研究策略文件 基础研究模型版本、工具权限、预算执行器与最终审计标准
可继承经验 H 实验记录、失败原因、已验证发现、数据与候选版本 来源可追溯；对照组获取信息的规则预先确定

选训练分支或服务分支之一完成主实验，再用另一类任务或不同配置检验迁移。先限制候选改动范围，确保每轮都能追踪哪个对象改变。

模型或服务变好，只能直接支持对象层改进。要研究递归关系，须保留改进器的版本差异，并展示修订后的机制实际参与下一轮实验设计；一段新增反思文本只有被后续决策使用，才构成相应机制证据。系统不必修改作为基础能力的 LLM 权重才能开展这种研究，但报告必须准确说明改变的层次。

9.3 最小闭环

  1. 从相同起点建立模型/服务与研究改进器，记录初始能力及预算。
  2. 改进器选择实验，生成候选，执行训练或服务测量，并接收开发反馈。
  3. 汇总候选、失败和资源使用，提出下一轮研究策略的修改。
  4. 检查新策略是否可执行、是否遵守预算与接口；保存版本，并在后续轮次实际调用。
  5. 对候选模型/服务进行独立评价，同时比较原改进器与继承后的改进器在新研究任务上的表现。

允许改进内部反馈与候选排序方法，但最终审计集、结果判定和预算执行器由外部固定。审计内容不进入改进器的提示、检索、生成数据或奖励；被反复用于选策略的成绩归为开发反馈，不能继续当作独立终评。

9.4 对照组与归因

条件 研究方式 主要回答的问题
R0 预先定义的简单搜索/调参方案，例如随机搜索或适合该空间的常规优化器 Agent 研究是否优于有竞争力的自动化基线？
R1 固定研究策略的 Agent，可读取同样形式的实验历史并更新被改进对象 固定的自适应研究过程能达到什么效果？
R2 使用相同基础研究模型，允许研究策略自身修订并被继承 额外的策略修订是否有净收益？
R3 继承/重置消融：在共同检查点分叉，分别使用修订策略与原策略 收益是否来自改进机制，而非更好的起始模型或更多历史？

“固定策略”允许根据新观察作决策，其实验记录也可以增长；固定的是决策程序或协议。R1 必须具备合理的反馈利用能力。

R3 分叉时对齐被改进对象、实验历史、可用数据、工具、基础模型和后续预算，只改变采用的改进策略。至少在多个可独立重复的研究任务上比较；同一研究过程的多轮记录不充当独立样本。将冻结后的修订策略用于未参与其形成的新任务，是检验迁移的一项独立实验。

同时报告两种口径：从原始起点计入策略演化成本的总收益，以及已获得该策略后在新任务上的增量效率。研究模型调用、教师数据、失败训练、候选测试、GPU/CPU 时间和人工审核都计入对应预算；相同轮数不等于相同资源。

9.5 指标、失败与达标

对象层指标沿用旗舰 A/B：留出任务质量、能力退化、有效吞吐、时延和成本。改进器层指标包括：达到预定目标所需资源、固定预算下最佳候选质量、质量随累计投入变化、可复现有效候选比例、跨任务迁移、回退和人工补救。单次自评提升或最后一轮的最高分不足以支持结论。

预先固定主要比较和资源上限，保存完整候选谱系、被拒绝的更新、策略版本、原始测量与停止原因。样本与重复次数根据预实验波动和效应规模制定；资源不足以估计效应时，结论限定为机制可执行性。

L3 达标： 两层闭环可重放，R0—R3 对照成立，能够区分对象改进、历史积累和策略继承，并解释一类失败或平台期。该实验可同时支撑相关模块，但仍需逐模块核对证据。

L4 研究入口： 提出有贡献的继承机制、策略表示、经验选择或评价方法，检验后续改进效率及迁移；或给出固定策略同样有效、递归成本抵消收益、反馈偏差使策略退化等有价值的边界结论。证明“修订会被继承”与证明“继承带来更有效的研究”分别验收。

9.6 既有 KCS 项目的位置

课程负责人已完成的 KCS 实践进入案例资料库，待分享演讲稿后提取知识资产、人工增量、反馈设计及其适用边界。它可用于连接 M5、M8、M9 和本实验的经验管理环节，无需重新实施一轮相同实验。后续若采用其中材料作为能力证据，应核对其原始记录与本版标准。

10. 统一实验与研究规范

10.1 比较对象与预算

一次运行的身份至少包括模型与 tokenizer 版本、权重或适配器、精度、harness、提示、工具、知识库、任务、推理引擎、硬件和时间。服务商不公开某项信息时记录“不可观测”，不能填入推测值。

模型选择评价至少包含任务质量、完成时间、失败与重试、工具调用、人工介入和总体成本。跨模型的 token 数不必然等价于相同计算预算；同时记录可获得的成本、设备时间和墙钟时间。

10.2 主要指标口径

指标 约定
任务成功率 满足预定义完成与质量标准的任务数 / 被评价任务数；说明重试政策
每个成功任务的成本 比较期间全部相关成本 / 成功任务数，包含失败与补救；零成功时单独报告
人工投入 分别记录配置、标注、知识补充、审核、运行补救和后续维护
完成时间 从规定的请求起点到可验收结果；说明排队、重试和人工等待是否计入
有效吞吐 单位时间内同时满足质量与时限要求的任务量；与纯 token 吞吐分别报告
稳定性 多次运行的分布与置信区间，明确任务相关性和随机性
恢复能力 在预定义故障后完成或正确终止、升级的比例及代价

10.3 研究可信度

在正式比较前固定主要假设、任务划分、主要指标、预算、停止条件和允许的差异范围。保留调参记录，避免从许多候选中挑选最好结果后使用未经修正的置信结论。

统计分析以独立任务或适当聚类单位为基础，优先利用相同任务上的配对比较。多轮对话、同一来源的近重复问题和同一用户的重复任务，需要处理其相关性。除总体指标外，按任务难度、输入长度、来源和失败类型报告。

程序验证优先核对环境的真实结果。模型评审需要与人评或已知答案校准，并检查顺序、风格、冗长和自偏好等影响。评价者也属于需要验证的系统组件。

10.4 技术直觉与个人学习

每次关键实验前记录预测、理由、预期数量级和信心；实验后记录偏差、竞争性解释及下一项区分性实验；改变一个条件后再检验迁移。直觉的成长用预测与诊断质量观察，不用阅读数量或主观自信替代。

附录 A. 专题实验 E07：多轮任务的上下文压缩与恢复

本实验服务于 M5 的 L3—L4 学习，保留完整的可实施方案。主旗舰实验见第 8 节。

A.1 研究问题

在给定 token、计算与延迟预算下，设计目标相关的服务端压缩策略，检验它能否保持接近结构化 handoff 的下游任务表现，并明确相对完整历史的损失、成本和适用边界。

这里的“有效”是对指定任务分布、预算、指标和不确定性的经验结论。对通用开放任务，不宣称已经证明任意信息压缩无损；对受限状态字段，可以另外证明模式或状态不变量。

A.2 系统接口与不变量

设计一个由课程自行实现的压缩服务，输入包括目标、对话或事件、工具结果、结构化状态和预算；输出包括保留状态、摘要、证据引用、未解决事项和必要的检索指针。该服务是公开可检验的设计，不复刻或声称揭示供应商的私有压缩项。

需要单独保存并验证的字段包括：当前目标及其版本、有效约束、已执行动作及回执、关键事实与来源、精确标识符、已知失败、未完成项和可恢复工件。摘要不应覆盖可验证的事实记录。

A.3 基线与控制

条件 方法 用途
A0 完整历史 在能装入窗口的共同子集上提供参照；超窗任务标明不可用
A1 保留最近消息的简单截断 建立低成本基线
A2 普通会话摘要 检验无专门状态结构的摘要
A3 结构化 handoff 文档 对应可阅读、可交接的基线
A4 目标与预算感知的压缩 检验所提出策略
A5 压缩加可追溯检索 检验外部存储的作用，计入检索成本
A6 可用时的供应商 compaction 作为兼容模型上的黑箱参照，单独报告限制

先固定下游模型、工具、任务、压缩预算和压缩时点，比较算法。再把同一算法分别部署在客户端管理层和服务端，比较序列化、网络、延迟与运行效果。位置变化与算法变化分开检验。

如果引入 KV 量化或裁剪，另设“语义压缩开/关 × KV 近似开/关”的实验，避免把两种干预的收益混在一起。普通上下文改写后，应按新的输入重建或正确复用兼容缓存；删除文本不等于可以任意删除或保留原 KV，后者可能包含此前输入的影响。

A.4 任务与指标

任务至少覆盖：长程依赖、精确编号、目标中途变化、旧事实被更正、工具失败、部分完成、需追溯证据的结论、多次压缩和重新启动。任务生成器、开发题与隐藏审计题分离。

报告任务成功率、关键状态正确保留率、来源正确性、错误行动、重复工作、恢复时间、输入输出 token、压缩和检索开销、TTFT 与端到端时长。结果按压缩轮数、压缩比例和任务类型分层。

“接近 handoff”采用预先确定的非劣效或等效问题表达。若采用非劣效，定义允许的质量下降 δ；对配对差值 Q(A4)−Q(A3) 计算任务层面的区间，只有下界高于 −δ 时，才支持相应结论。δ 由任务容忍度在正式评测前确定；未检出显著差异不能直接作为等效证据。

样本量由预实验方差、δ 和所需把握度估算。少量任务与多次重复可以用于调试，不足以自动支持总体非劣效结论。相同任务的多个轮次或试次存在相关性，不能伪装成大量独立样本。

A.5 达标与研究贡献

最低交付为接口实现、基线、任务资产、状态模式、成本账、原始轨迹、配对分析和失败报告。结论可以是策略有效，也可以是某类目标变化使其失效。不能仅用更短的上下文或更低的摘要损失宣称任务能力被保留。
