## 环境发现

在项目根目录执行，首次使用下面的新运行目录；重复采集时换一个尚未使用的 run_id：

~~~bash
python3 scripts/probe_environment.py --check-torch --output runs/local-discovery-01/environment.json
~~~

当前 Windows Z 盘对应的 WSL 目录是 /mnt/Projects/ProjectLLMAgent。若当前终端工作目录不可用，可以先进入这个已确认的实际目录。脚本会拒绝覆盖已经存在的报告。

脚本不会安装依赖或启动训练。默认只发现包；加 --check-torch 后在独立子进程导入当前解释器的 PyTorch 并查询 CUDA，仍不执行 GPU 张量计算。nvidia-smi 可能受执行沙箱限制；这种情况会如实保存为查询不可用，不能推断主机没有 GPU。

输出采用新建模式，不覆盖已有证据。需要重测时更换 run_id。

## 建立运行环境的顺序

1. 确认选择的 Python 和 GPU 驱动；为课程建立独立训练环境。
2. 依据所选 PyTorch 官方安装矩阵安装兼容发行包，记录实际版本与包清单。
3. 做很小的 CUDA 张量前向/反向与内存分配验证。
4. 完成 U01/U02 的 CPU 正确性检查，再转 GPU。
5. 引擎实验单独建服务环境；不要为安装引擎而改坏训练环境。

本次只交付环境发现与设计，不提前写死尚未验证的安装命令或版本组合。

## 固定权重的未来信息依赖检查

2026-09-19 新增已运行的机制示例：

~~~bash
python3 labs/E01/future_token_probe.py
~~~

程序仅使用标准库，在固定参数的两个小注意力层中比较“未来 token 改变，较早位置的 logits 是否变化”。全部层采用因果 mask 时应保持不变；无 mask 是正对照，仅末层遮罩用于展示前层泄漏可以保留下来。输出还报告权重是否保持不变及优化器步骤数。

这不是完整 Transformer，也没有训练或模型能力评价。参考实现通过不代表课程的教学模型、GPU 或真实引擎已验证；下一步应把同样的不变性检查迁移到实际实现。
